# 当前题带学真人试用包（待开展）

状态：尚无参与者原始记录，没有学习收益结论。本文件是执行流程，不是已完成报告。不自动邀请或联系任何人。

## 准备

邀请 1–2 位愿意参与的同伴，每人使用独立本机数据目录，避免查看其他人的历史。先确认资料可使用、题干可答、评审答案核查无误。开发夹具的迁移题只能作候选，课程持有人应先确认；若学生已看过该题或答案则另换题，不能再称未见题。

观察者预先准备两个题包 A/B，匹配考点、难度、评分点和所需步骤，但使用不同材料与推理条件。系统组与直接模型组使用同 Provider、模型、2000 输出预算和合理导师指令。第1人先系统后直接，第2人反序；只有1人时记录顺序效应无法排除。不对同一人重复讲同一道题，避免记忆污染。原始资料比较与相同相关证据比较分开记录。

学生侧只提供题目、材料和操作入口；答案与评分点由评审侧保存。开发回放中的学生消息、模型小检查、脚本作答都不算真人成绩。

## 一次流程

1. 记录参与者代号、日期、已有基础、自评和是否看过材料。独立完成前测：关闭带学，保留原答与耗时；观察者不提示解法。
2. 围绕当前题使用带学。让参与者自行找到当前题、聊天入口、来源和正式提交。观察者只在阻塞时介入，每次记录时间、原话及代操作，不能把观察者帮助记作系统效果。
3. 保存完整对话、帮助暴露、模型用量、正式作答及复核。让参与者解释哪里理解了、哪里仍卡住；“懂了”不作掌握证据。
4. 撤去带学与刚才答案，使用预先封存的匹配未见后测。独立作答，保留全部原答，按事先确定的条件判分，等价表达用实际数据或推导核对。低置信或异议交人工核查，不能只让同一模型自评教学成功。
5. 条件允许时隔天做另一道未见题，记录间隔、期间是否复习及额外帮助。无法执行则明确“延迟效果待验”。
6. 记录操作困难、无法理解的反馈、错误肯定、引用查不到、重复讲法和等待成本。失败同样保留；中途退出记录原因。

## 记录模板

每位参与者复制填写一份，原答与对话保存在本地私有验收目录，不上传仓库。

| 项目 | 原始记录 |
|---|---|
| 代号、日期、环境、代码版本 | 待填写 |
| 题包 A/B、来源 hash / 页码、分组及顺序 | 待填写 |
| 前测原答、耗时、评分及核查人 | 待填写 |
| 带学 session/task/turn ID、完整输入输出文件 | 待填写 |
| 观察者介入时间、原话、代操作和帮助内容 | 待填写（无介入也须记录） |
| 正式作答原答、提示依赖、异议及复核 | 待填写 |
| 未见题封存时间、是否提前见过、后测原答 | 待填写 |
| 后测逐点依据、错误条件、等价答案执行结果 | 待填写 |
| 延迟间隔、复习或额外帮助、延迟题原答 | 待填写或待验 |
| Provider/模型、每组轮数、token、耗时、失败 | 待填写；价格未配不能把0估算当免费 |
| 操作问题、退出原因、参与者原话 | 待填写 |

结论分为工程操作、模型行为、真人独立应用三列。单人单题成功只能说明该次表现；无前测、泄露后测答案、观察者提示或题目不匹配时注明混杂因素，不输出教学提升百分比或普遍优于直接模型的结论。
