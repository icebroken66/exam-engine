这些是维护和交接风险，不等于现有功能全部不可用。优先做有边界的渐进整理；不重写整个项目，不以更复杂框架作为架构成果。

## 2. 模块职责与依赖方向

以下为目标边界，目录和文件名只是候选，不表示已建成。每个实现 PR 根据实际依赖确认最小拆分。

| 领域 | 负责 | 不负责 | 当前入口 |
|---|---|---|---|
| 资料与证据 | 接收、解析、转录确认、来源生命周期、检索 | 决定学生掌握或改成绩 | parsing / visual_parsing / source_lifecycle / retrieval |
| 题目与范围 | 课程范围、题库候选、生成、验题、来源关联 | 会话推进、聊天评分 | learning_sessions 部分职责、exam_extraction |
| 学习会话 | 当前任务、阶段推进、并发版本和学习事件 | 具体讲解策略、PDF 解析 | learning_sessions |
| 判分与纠错 | 正式提交、复核、人工更正和状态重算 | 根据聊天宣告掌握 | learning / learning_sessions 部分职责 |
| 当前题带学 | 消息、上下文、帮助暴露、恢复和引用 | 自动提交、改成绩、切题 | tutoring |
| 跨轮次证据 | 从有效作答投影可参考记录及复习建议 | 复制旧分数、跳过诊断、自动运行复测 | learning_evidence |
| HTTP / 前端 | 校验输入、调用业务、展示状态和显式操作 | 复制业务规则或依赖教师私有答案 | main / api.ts / 各 Panel |

依赖方向：HTTP → 业务入口 → 明确职责的模块 → 数据库 / 网关 / 存储；前端组件 → 类型与 API 客户端。共享的会话读取、版本检查、事件与引用能力应有显式接口，带学不再依赖学习服务的私有实现。只抽取确实有多个调用者且语义相同的能力，不创建万能 utils 或共享可变会话对象。

拆分必须保留：事务提交位置、异常与 HTTP 语义、来源后校验、版本冲突、模型调用次数与顺序、回复保存 / 回执、帮助独立性、人工纠错优先权及原始历史。移动函数不能顺带改变这些行为。

## 3. 工作方式

1. **一次只推进一个主要实现 PR。** 下一张卡可以准备材料，但不同时修改其依赖的公共文件。用户另行明确要求并行时，先分配文件边界和合并顺序。
2. 每张卡先写清用户或维护问题、范围、不改什么、依赖、影响文件与验收。分支从最近已验收基线开始，使用短期分支；不用旧的 feature/next-development 作为新基线，也不删除该历史分支。
3. **整理结构与改变行为分开。** 文件迁移或函数提取 PR 不改提示词、评分规则、schema 字段、数据库、API 语义或界面交互。真实故障修复单列；若阻断整理，只做最小前置修复并记录依赖。
4. `main.py`、`learning_sessions.py`、`schemas.py`、`models.py`、`api.ts`、共享 CSS 是合并热点。卡片列出触及内容；确需改公共接口时，接口定义与全部调用方迁移在同一个可验证 PR 完成。
5. 一个 PR 的状态只用：待开始 → 进行中 → 待验收 → 已完成，或阻塞。等待真人反馈的任务独立标待反馈；不能让一项缺失真人结果长期掩盖已经完成的工程工作，也不能把工程完成当效果已证实。
6. 不因本计划自动执行付费回放、发送邀请、推送、发布或改正式学习库。后续实现按当次授权和既有执行约束开展。

## 6. PR 审阅与验收规则

使用 `.github/pull_request_template.md` 填本地说明即可，不要求发布。每次结果注明基线和最终提交；工作区运行则记实现 hash，不把父 revision 冒称最终实现。

- 结构 PR：重点验证调用链、事务 / 异常 / 接口和既有行为保持；不为函数搬家反复付费回放。
- 行为 PR：除适当回归外，附修复前失败与修复后样本；学术结论有原件 / 执行 / 人工核查依据。
- 数据变化：本维护阶段默认不需要；确需迁移时另立契约、备份 / 回退与历史一致性验收，不能顺手改 schema。
- 证据：工程、模拟 API、真实模型、真人分别列；测试数只描述对应提交，未运行写明原因。私有原件、密钥、完整个人对话和数据库不入库。
- 文档：状态只维护工作区 03，阶段只维护 04，PR 范围只维护本页；细节与原始失败留在 evals / records。完成后更新相应入口，不逐次追加新的总计划。
