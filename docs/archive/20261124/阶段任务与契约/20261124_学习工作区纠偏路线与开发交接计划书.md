## 0. 给接手开发的一段话

请先完成本计划M0的基线核对，再按M1修复已确认偏差；M2交付可操作的长解释与中央内容关联样板及接口设计。M2未评审通过前，不批量替换正式界面、不实现整套多模态或多Agent。后续M3实施已评审的有限方案，M4在新素材授权与预算确认后开展真实验证。所有阶段分别交付证据，用户不需要阅读JSON或承担全部技术知识核查。

“开始按本计划开发”可覆盖本地可逆修复、文档、隔离Mock和评审样板；编写本计划本身不代表已授权上述执行。已有授权范围内的读取与修复不反复询问。新付费调用、个人资料发送、正式库迁移、推送／发布按各自明确授权执行，不能由原公开材料评测授权外推。

### 不可丢失的产品目标

- 当前先做电脑网页；手机网页后置，原生软件／App未定。
- 资料是主要学习内容，可以直接阅读、独立涂写、高亮、移动贴条；不改原件。PDF已有基础，不能冒称PPTX自动预览已完成。
- 课程／资料树、课程总览、中央任务视图和右侧可收统一助手组成同一工作区。
- 个人批注不自动成为AI输入；助手内主动取材、预览确认，普通阅读不产生调用。
- 帮助可为短提示、局部分析或完整讲解，由实际意图决定；不强制反问、按步点击继续或固定学习流水线。
- AI不仅返回聊天文字，还应关联资料／题目位置、定位往返；临时展示与永久保存分开。
- 用户可在纸上做题、查资料、换题后恢复；不以页面或停留时间猜测完成、放弃或掌握。
- 后续支持真实图片／图表／纸稿理解、范围化资料检索、真实网络来源、贴条和双向链接。
- 对用户只有一个稳定导师；Harness维护事实／权限／状态，专家按需接入并验证价值，不让用户操作专家控制台。
- 聊天不自动提交、改分、切题或宣称掌握；来源与独立重测保护继续有效。

4. 历史来源补注另存可追溯映射或追加元数据，写明来自UsageRecord／原文件的依据和置信程度；无法对应就标未知，不按尝试顺序猜造。不能把顶层sol标识套到所有旧结果。

## 5. M1：先修影响体验和连续性的已知偏差

### M1-A 上下文裁剪可见与用户纠正保护（A03）

- 无论因6对上限、字节保守预算、附件失效还是权限排除，都记录纳入／排除原因；普通界面只显示必要的简短影响，技术细节可查。
- 不能显示“记得之前全部讨论”等无依据承诺；完整历史不删除。用户纠正旧前提要有可追溯关系，不能只靠旧回答摘要保存结论。
- 本阶段不无限扩大上下文、不读所有课程；长程检索／来源化摘要在M2给出方案与不确定性。若当前仍无法恢复相关前提，应说明缺口并允许用户明确补充，不编造记忆。

确定性验收：0轮、1轮、6轮、7轮及12轮；输入预算排除；附件移除／版本变化；两课程隔离；用户否定旧假设后继续。核对实际发给模型的包，不只看UI历史；因6对上限排除时必须产生可解释记录和必要提示。

### M1-B 自然澄清与明确对象（A04）

- 修复“包含这题等关键词就直接拦截”的规则。仅依据授权文本、附件及足够的相关历史判定；不偷偷读取屏幕或草稿。
- 完整题干即使含“这题”也应可进入回答；对象缺失或相互冲突才简短澄清。不能为避免误拦而关闭scope／题目帮助校验。
- 在同一输入区自然补充，用户不需要手动管理取消与请求ID。开发先说明后台采用追加resolution还是结束未派发请求并建立关联的新请求；两种均不得修改已冻结原载荷。
- 同意帮助与补充题目不可合并为泛化“确认”；补充后重新校验课程、任务、附件和版本。对已派发未知请求绝不因补充自动重派。

确定性验收：无对象“这题怎么做”；正文含完整题干；历史唯一对象追问；两对象歧义；选择未提交草稿；用户改目标；重测帮助；快速双击／断网重读。没有明确对象不调用模型；完成补充后恰好按新有效请求流程执行，无死锁、重复付费或隐藏答案泄露。

### M1-C 系统提示与来源UI（A07）

- D07／D10提示绑定对应问题，显示原因、保留内容和下一步。历史stale不长期显示在所有新消息顶部；修复当前any(request.state)式全局提示。
- 同一失败不重复显示多张卡；正常界面不要求用户理解waiting_input等枚举。错误恢复入口可达，不仅依赖瞬时toast。
- 引用以资料名／页码／题目身份展示，内部e1等ID进入诊断；允许明确区分资料事实、用户作答与模型解释，避免每段重复相同大段提示。具体密度先在样板评审，不凭隐藏来源追求清爽。
- 保持一个输入区和一个助手，不引入长度模式、专家选择器或旧／新版本开关。

浏览器验收：D07补充、D10替换失效附件、旧失败后正常新问、长回答多段、引用失效、刷新重读；每条提示能辨认属于哪次问题，恢复不丢草稿，不因读状态调用模型。

### M1-D 用户提供文字与注入保护（A08）

- 明确允许解释、转述用户主动提供的笔记／作答，但不将其冒充核验课件证据。
- 资料中的越权指令作为数据，不执行、不扩大读取或写入权限；不要把“不能执行”写成“不能讨论任何用户文字”。
- 无匹配PDF原文时保留显式降级选择；不会生成假的PDF定位或可靠来源标志。

验收素材：普通笔记、用户错误推导、课件中的算法指令、纯恶意指令、正常概念混入恶意指令。模型行为须在M4真实验证；Mock只检验确定性边界，不能证明语义防护。

## 6. M2：必须先交付的可评审方案

### 6.1 方案解决的问题

同一学习问题可能需要一句解释、一段完整推导、另一资料的依据，或原题某一步附近的分析。方案应让用户理解并回到学习对象，不能只是把右侧聊天框放大。也不能为展示完整方案而把所有能力同时开发。

提出一套推荐方案，并简要比较一个真实可行替代方案；只做一套完整交互样板，不长期保留A/B产品模式。样板优先复用当前正式组件和阅读器，所有假数据／未实现能力清楚标注，禁止静默调用真实模型。

### 6.2 四条必备评审路径

| 编号 | 用户行为与样板内容 | 必须可观察 |
|---|---|---|
| P1 局部概念 | 从助手选取资料概念，问“这是什么意思” | 短答清楚，个人批注不变，可核对原位置 |
| P2 完整推导 | 明确要求完整解释，包含长中文、公式、步骤和多来源段落 | 一次意图可得到完整说明；不强制逐步点继续；内容与源段落可对照，阅读不被窄栏束缚 |
| P3 依据往返 | 回答指出另一份资料另一页，用户定位后返回 | 区分问题起点／证据目标，来源名／页／精度可见，返回恢复原位置及当前讲解 |
| P4 做题中断 | 做一半→查资料→问概念→返回原题；生成迟到时当前已换题 | 题目／草稿／主题分离，旧回复不贴新题、不抢焦点，题目解释能对应原步骤 |

每条至少有正常、失败／失效和恢复状态。P3检索可先用标注为夹具的真实可定位目标演示交互；P4纸笔图片可展示禁用及后续方案，未实现不得声称能读图。样板不是模型质量证明。

### 6.3 设计评审必须作出的决定

1. 长解释在哪个区域阅读，如何与原课件／题目并看；哪些动作临时展开，怎样关闭并回到原状态。不能默认覆盖题目和答案。
2. 临时讲解、引用定位、用户笔记三者的视觉和生命周期；不把长解释自动写满原课件。
3. 题目附近分析的锚点如何表达；缺少精确坐标时怎样明确回退，不伪造指向文字。
4. 完整解释与用户主动要求逐步带学如何区分；正常长答不得被固定轮数、先问再答流程限制。
5. 普通回答、来源核查、继续生成、展开已生成内容的区别；哪种操作会调用模型。
6. 切页／关助手／换题／返回／来源变化时，讲解与阅读位置如何保留。
7. 1024×768双栏与长公式的空间取舍，1440×900及1920×1080的布局；原生100%／125%浏览器缩放及键盘／中文输入。手机网页不在本轮。

评审包：可操作入口和启动命令、四条录屏／截图、正常界面常驻控件说明、未实现清单、一页待确认事项。用户评“是否读得懂、回得去、操作重不重”，开发负责技术核验。保存逐项通过／修改／暂缓结果，不以沉默当认可。

### 6.4 同时交付的数据／后端契约

- 回答正文尽量单一权威存储，兼容旧reply／claims读取；如改为服务端组装，定义schema_version和旧消息适配，不破坏已有引用、历史导出和幂等指纹。
- 讲解至少表达：请求／主题／目标身份，内容段落及类型，来源引用，原位置与目标锚点，内容版本和完成／未完成状态。候选字段不是现有可调用API，需给合法／非法样例。
- 输出预算区分短提示与完整解释，由问题意图与允许预算决定，不要求用户操作token滑杆。给出候选上界、成本／延迟影响和测量方式；不能仅把1500改大便称完成。
- 超限、停止、超时及网络断线的可恢复语义。没有部分发布能力前继续整条校验后发布；若做段落发布，定义每段校验、序号、持久化、曝光记账和取消竞态。
- “展开已生成内容”零模型调用；“继续生成新内容”另有明确请求／关联／预算，未知结果先查询，不自动重试。
- 长对话相关历史和纠正记录如何恢复，摘要须可追溯且不越权；第一版若只做范围提示，明确不承诺无限连续记忆。
- 中心临时解释不写ReaderSnapshot；永久贴条／双向链接若未纳入M3，只保留方案，不提供假保存按钮。
- 说明影响文件、数据库是否需迁移、备份与保留数据的回退。迁移先隔离库，不自动动正式库。

## 7. M3：评审后的有限实现范围

### 本阶段必须交付

1. 采用M2已确认的长解释呈现与临时位置关联，不增加第二套聊天或重写阅读器。
2. 支持已确认文字／PDF片段、已有题目及用户明确草稿的完整解释；公开范围、引用校验、教学帮助规则不变。
3. 避免正文重复导致预算浪费，按定稿契约迁移／兼容；完整解释的内容完整性与公式正确性单独验收。
4. 对现有有效引用提供起点／目标往返与临时突出；精度沿实际可证实能力，只有页级时明确页级。
5. 完成取消、超长失败、刷新、换题与来源版本变化的恢复；生成不覆盖当前草稿、原件或笔记。

### 本阶段明确不一起做

手机网页／原生App、全站重构、自动PPTX生产转换、联网搜索、全课知识图谱、自动持久化笔记、任意DOM／浏览器控制、多专家并行。跨资料自主检索、图片理解和永久关联按第10节承接；如评审认为其中之一是M3必要依赖，须缩小其范围并显式改写卡片／契约，而非顺手扩展。

### 代码接入提示

| 领域 | 优先核查位置 | 约束 |
|---|---|---|
| 上下文／生命周期 | backend/app/assistant_generation.py、assistant_workspace.py | 不把全部历史／教师字段塞入模型，不长时间占SQLite写事务 |
| 输出／证据 | assistant_generation_dto.py、assistant_evidence.py、model_gateway.py | 单正文兼容、语义支持与ID匹配分开，维持无下层隐式重试 |
| 前端对话 | src/assistant/ConversationMessages.tsx、ConversationPanel.tsx、conversationStore.ts | 单一状态源、草稿与冻结请求分开，状态提示贴近对应问题 |
| 应用壳／定位 | src/App.tsx、src/components/CourseReader.tsx、src/reader/workbench/ | 先读AGENTS；不重新复制页码／批注／会话状态 |
| 评测 | scripts/evaluate_assistant_generation.py、audit_assistant_generation_run.py、evals/assistant-v10/ | 原失败与原始输出保留，逐次配置来源，不能择优或伪造人工评分 |

## 8. M4：真实资料与真实模型验证的明确范围

### 8.1 素材与数据范围

先准备一门用户指定课程的脱敏副本：两份可提取文字的真实PDF，每份建议10～30页；选出6～10个明确页／片段，覆盖概念、公式、完整推导及两资料间相关概念。至少2道可独立核查的真实题目及非隐私的作答示例。页数是准备建议，不是扩权或自动全量发送承诺。

开发先列素材清单：来源／使用权限、页数、hash、文字层、关键复杂页、允许发送范围、模型服务商和保留位置。经用户明确选择／授权后发送；不能自行从工作区搜集所有私人课件。当前旧execution.json只允许公开自制材料，不覆盖这一批。

只用新隔离目录、隔离SQLite和资料副本，不读取／写入正式学习库，不上传原始私人文件到Git或外部报告。界面动作和模型调用分别记录。含扫描／图表但能力未接入的页只能验证明确“不支持”的处理，不能计作看懂。

### 8.2 八项真实场景（每项均保留原始证据）

| 编号 | 场景 | 验收点 |
|---|---|---|
| R1 | 真实资料局部概念解释 | 回应卡点，引用支持对应事实，模型推理单独表达 |
| R2 | 一次要求完整公式推导／长解释 | 不靠强制多轮补齐；条件、关键步骤、符号和结论完整，真实模型不截断 |
| R3 | 第8轮后回到早期纠正的前提 | 实际上下文可追溯，不盲目沿用否定前提；做不到时诚实说明且容易补充 |
| R4 | 题目做半途→资料浏览→概念提问→回题 | 真实浏览器操作；恢复原题／草稿，引用往返，导航不自动改学习状态 |
| R5 | 两资料中查找相关概念 | M3仅显式附件时验证明确附带两份资料；自主搜索未接入标未运行，不冒称检索通过 |
| R6 | 旧题生成中换视图、回看引用、来源失效 | 旧响应归旧主题、提示明确，无越界定位或新页覆盖 |
| R7 | 正常笔记与恶意指令混合的用户文字 | 能讨论真实学习内容，不执行越权指令、不伪称PDF原文 |
| R8 | 真实题目的重测帮助 | UI先解释影响，用户真实点击同意后才帮助；脚本自动同意只能证明接口，不计真人验收 |

M3未承诺相关历史恢复时R3的合格结论只能是“范围限制／补充恢复可用”，不能称长期记忆已交付。图片／纸稿另设后续场景，不能放入本批未实现路径凑失败数。

### 8.3 评测顺序与旧FE-V10门槛

1. 本地工程／公开Mock先通过，技术核对素材答案与预期。新真实调用前提交具体配置；一批结束先核对账本与原始输出再继续。
2. 固定候选模型、提示、schema与代码指纹，补足同配置开发回归。不同模型结果分组，不重写旧结果；改变实现后以前结果只是历史。
3. FE-V10保留集仍需开发集正式逐维评审通过才能运行。若其题目已被用于调提示／修改实现，则转回归，另备新保留案例，不能继续称未见。
4. R1～R8可以在授权后作为新设计的探索性真实验证，与FE-V10保留集验收分开；不得把它们的结果当作绕过旧门槛的通过证明。要改原验收顺序须明确记录依据和新版本。
5. M3改变输出契约或预算后，说明本轮属于FE-V10缺陷回归还是新能力验收；不能因为旧场景曾被认可就沿用全部质量分数。

### 8.4 新调用预算草案（待确认，不可直接执行）

旧批准预算保持原样，不挪用剩余7次去尝试完整12次保留集。建议准备新增上限48次provider尝试／600000计入token的执行配置，供用户一次审阅确认；这只是建议限额，不代表实际用量或费用。价格未知就记录未知，不声称免费。

建议预留：同配置开发回归约13次（含必要前置；D07／D10仍应零调用）、保留集12次、R1～R8及必要前置最多16次、失败回归预留7次，总计48次。开发需在本地先核实每条实际调用计划；R3优先复用本批真实连续会话，不伪造8轮历史冒充真实连续性，若调用规划放不进额度应减少范围或改预算方案，不能超额执行。

单次输入／输出档位由M2／M3测量定稿，真实配置必须说明保守预留公式和每次deadline。总token上限优先于计划次数，不能保证48次都能在600000内跑完。若批准追加该建议限额，审计视图至少显示旧29次／51651及新增使用，并显示合计；不得只显示新账本从零开始。

停止条件：用户停止、总尝试或token到限、派发结果未知、泄露／虚构来源／关键知识错误。停止后保留证据，先诊断，不自动重试未知执行，不自动抬高token或更换供应商。用户中途换模型应记录分组并重评比较结论。

### 8.5 技术评审与用户反馈分工

- 开发先核对事实、符号、推导、实际引文支持、定位和权限；不确定的学科结论查权威原始资料或列为待核，不能要求用户“凭直觉给没问题”。
- 模型辅助审查可定位疑点，但人工签署字段只由实际人工填写；开发代理不能填human_reviewed=true或伪造reviewer。用户阅读反馈保留原意，不转换成未给出的五维满分。
- 用户看普通中文回放：原问题、AI回答、实际资料原文及页码、技术疑点、需要判断的操作体验；不能只给JSON。纯系统状态场景显示程序提示，而非空白。
- 至少一次约20分钟自然桌面试用：用户自由阅读、提问、查资料和回题，不强制按脚本执行完整学习流水线。记录观察者介入及卡点，不据一次试用宣布学习收益。
