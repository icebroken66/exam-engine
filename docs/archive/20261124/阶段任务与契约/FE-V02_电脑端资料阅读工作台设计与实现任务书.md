# FE-V02：电脑端资料阅读工作台设计与实现任务书

日期：2026-11-23（北京时间）｜版本：1.0｜状态：任务书已编写，设计与实现待开始。

需求依据：[资料学习工作区讨论记录](../原始讨论与设计/2026-11-22_资料学习工作区讨论记录.md)。前置：[FE-V01 任务书](FE-V01_课件阅读与批注技术验证任务书.md)、[实施与验收报告](../实施验收与复核/FE-V01_开发与验收报告.md)。任务状态只在[开发计划](开发拆分与PR计划.md)登记。本轮授权为编写任务书，不代表开始代码实现或通过验收。

## 1. 问题与目标

FE-V01 已有独立 PDF 阅读、选择、三种批注、本机恢复及模拟引用能力，但界面以技术验证为主。用户明确不满意“整体像演示页面，缺少成熟产品的布局和细节”。本阶段复用已有能力，制作可持续使用、可继续接入业务的电脑网页阅读工作台。

核心路径：打开资料 → 阅读 → 选择内容 → 提问或批注 → 查看解释中的引用 → 定位与返回 → 管理笔记 → 退出后继续。

完成后必须具备：统一的设计规范、可操作的桌面工作台、完整的关键状态、真实内容与交互验收证据。不得以漂亮静态截图、增加卡片／图表或隐藏失败状态代替交付。

## 2. 范围

| 本轮完成 | 后续任务 |
|---|---|
| 电脑网页布局、控件、层次与细节设计 | 手机网页、原生 App、全站改版 |
| 复用 PDF 阅读与三种批注，加入本机笔记集中浏览 | 重写 PDF 引擎、PPTX 浏览器内编辑或自动转换服务 |
| 按需打开的助手面板、上下文、固定解释与引用演示 | 真实 AI、联网检索、正式聊天后端 |
| 真实本机保存状态、阅读恢复、错误与空状态 | 账号、云笔记、跨设备同步、正式存储接口 |
| 选定工作台范围的 BoardUI 基础组件与设计规则 | 一次性迁移全部旧页面和组件库 |
| 明确可发现的工作台入口，保留旧课程路径 | 正式课程资料读取／版本接口及题目双向关联实现 |

当前支持 PDF，PPTX 人工转换限制沿用 FE-V01。打开对话时说明“未连接 AI”；固定回复标为“示例解释”。本机存储范围持续可见但不反复占用大段正文。

## 3. FE-V01 前置收尾与进入条件

开工先核对最新代码和证据，不能只依据旧报告。补测失败日志与等待原生缩放的文件不等于通过；逐项写清补测是否解决原问题。

- 设计草图和组件映射可先开展，不因非阻塞报告整理无限等待。
- 定位精度、原件只读、身份隔离、已保存内容恢复、保存失败反馈、笔刷取消与贴条历史属于核心前置。相关失败必须先修复并复测，再将依赖能力标为可用。
- 真实课件保真、125% 浏览器缩放、笔迹／贴条实测、完整历史与键盘、性能剩余项按原任务书补齐；不降低原阈值，不将 PDF 成功记为 PPTX 全面成功。
- FE-V02 可交付设计评审版本，但最终完成要求 FE-V01 范围验收收口。若仍有阻塞，两个任务分别记录状态，不能靠改版绕过。
- 实现前固定可追溯基线：记录精确 HEAD、工作区差异、FE-V01 源码指纹与证据。当前大量实现尚未提交，先区分用户文档与本任务代码，按仓库规则固定已验收成果；不得丢弃未提交内容、擅自合并 main 或推送。

## 4. 设计工作流与评审点

### D1：任务、内容和组件映射

先读当前 ReaderLab、PdfPage、AnnotationLayer、存储与坐标契约。列出“用户任务 → 页面区域 → 所需状态 → 现有实现 → BoardUI 组件或业务组件”。检查官方 skill、目录、实际源码与用例，不猜 props，不重造已有控件。

样本至少包括一份允许本地使用的真实长课件、公开混合内容夹具、无文字层页面、长文件名、长笔记和长解释。私有原件与截图不入库。

### D2：两套结构比较并收敛

以同一份内容和同一状态制作两套有实际差别的桌面结构草图，比较工具位置、目录／笔记组织及阅读面积；无须先做两套完整应用，也不得以换颜色冒充布局差异。保留已确认的中央资料阅读与右侧按需助手，原先“题目居中、资料辅助”的布局不得复用为既定结论。

提供 1440×900 的默认阅读、批注、助手打开三种状态及 1024×768 的收缩方案。每套说明一个优势和一个实际代价。选定推荐布局并给出可操作评审入口，再请用户确认方向；已确定的通用需求不重复询问。用户尚未反馈时可继续组件、状态和测试准备，不把未确认方案批量推广到其他页面。

### D3：精细样板与实现

收敛后完善一个工作台，而非长期维护 A/B 开关。优先复用正式组件和真实阅读数据，设计评审开关与故障注入收进开发专用入口。固定解释及本机存储边界仍明确标识。

每轮提交：本轮解决的问题、可操作版本、同位置前后截图、实际变化和剩余问题。用户反馈记录到设计决策，不用不断生成全新风格替换前轮结果。

## 5. 工作台与交互要求

### U1：整体框架与阅读优先

- 明确工作台身份、当前文件、页码和保存状态；顶部保持紧凑，不放大段教学宣传、调试数据或无实际数据的进度统计。
- 资料是主要区域；缩略图／笔记导航可收起，助手按需出现并记住用户选择。无需增加全课程侧栏，不为不存在的课程关系编造面包屑。
- 中央课件保持原貌、正确比例和可读性；横版、竖版、长表格均支持阅读区域内滚动。首次打开适应可用区域，用户显式缩放后打开／关闭面板不得静默覆盖该选择；“适应宽度”模式可随可用宽度重新计算。
- 工作台不出现整页横向滚动，必要滚动限制在课件、导航和面板内部。内部滚动顶部渐隐按 BoardUI 规则实现，顶部为零时不可遮挡正文；固定标题和工具不随内容丢失。

### U2：阅读和批注工具

- 2026-11-23用户确认进入D3后补充观看体验要求：顶部工具采用成熟文档软件的紧凑分组与图标文字层次；连续缩放（百分比、滑杆、Ctrl滚轮）、适应整页／宽度、专注及原生全屏必须可操作。退出专注／全屏恢复之前视图，不重写批注坐标。此增补不视为用户最终视觉验收通过，原125%浏览器缩放要求不被课件缩放替代。

- 阅读、文字选择、区域选择、笔刷有明确选中状态与文字提示。常用动作直接可达，低频设置折叠；1024px 下可调整工具分组，不得靠多行堆满工具挤掉正文。
- 图标控件有可访问名称和悬停／焦点说明。按钮按真实状态禁用，禁止仅靠颜色表达模式与错误。
- 笔刷颜色／宽度、高亮、贴条、撤销／重做、删除选中项、隐藏个人批注与实际功能连接。改变颜色或宽度作用范围明确，不静默改动已有全部笔迹。
- 选择内容后出现贴近选区的操作或稳定的上下文操作区；不遮住选区与必要正文，边缘选区操作仍可达。提供“问 AI”“高亮”“添加贴条”，取消后恢复阅读。
- 保留 FE-V01 的笔刷失焦／取消保护、批注历史、文档隔离、精度和保存语义；工具焦点不能造成误绘或意外翻页。

### U3：贴条与笔记集中查看

- 贴条可编辑、拖动、删除；编辑和拖动明确分开。支持收起／展开以减少遮挡，收起后仍有位置标记；该动作不删除内容。首版不要求自由调尺寸和富文本。
- 集中笔记列表按页组织，区分笔迹、高亮和文字笔记，显示文字摘要或类型／页码；支持页码／文本检索，非文字笔迹不伪造可检索语义。
- 点击列表项定位到原页批注并短暂突出；只查看不能修改笔记，也不能把 AI 临时指示保存成笔记。
- 删除提供撤销，编辑／移动结束后走原有自动保存。恢复时收起状态若新增存储字段，必须兼容旧 FE-V01 数据，不静默重置批注。若需要新 schema，提供迁移、失败保护和回退说明。

### U4：助手与引用呈现

- 2026-11-23用户纠偏：AI学习助手是贯穿资料阅读、做题、答案理解的工作台级功能，通用入口与右侧面板属于外层应用壳，不嵌入PDF工具栏／阅读器内部。PDF选区的“向助手提问”只是附带上下文的快捷动作；没有打开PDF时通用入口仍可发现。此卡仅实现资料上下文适配和演示，不宣称旧做题页面或真实AI已接通。
- 通用入口打开不得清空既有关联上下文或草稿。不同内容视图提供上下文适配，切换视图不等同于新建对话；跨视图会话状态与正式做题接入需独立实现和验收，不能把当前按文档暂存误记为软件级会话持久化。

- 默认按用户选择打开；首次未设置时收起。右侧面板有清楚的关闭入口，支持键盘，关闭后焦点回到触发控件或选区操作。
- 输入前显示当前文档、页和选区摘要，可展开核对、移除或明确替换。翻页不悄悄替换已有提问上下文，草稿不得丢失。
- 解释样板包含长中文、列表、公式及多个引用，复用已有安全 Markdown／数学渲染能力；先核查复用的样式依赖，不把旧页面全局 CSS 引入工作台。
- 固定内容明显标示演示，不能以可发送按钮暗示真实模型服务已接通。可以“演示解释”触发夹具；不实际发送，不产生正式学习事件、成绩或帮助记录。
- 课件引用卡显示实际可定位的文档／页，默认用户点击再跳转。区分个人批注与 AI 临时指示，保留清楚的“返回原位置”；沿用版本校验和无效引用反馈。
- 本卡不伪造网络来源或联网状态；未接入的外部查证、题目关联使用文字说明或省略，不提供无响应主操作。

### U5：状态与恢复

必须设计并可复现：首次空状态、文件读取中、正常阅读、无文字层、无笔记、笔记检索无结果、选区已建立、面板打开、保存中、保存失败／重试、已保存、坏文件、版本不兼容、无效引用、重开原文件恢复。

- “保存成功”沿用实际存储事务结果，禁止用视觉延迟假装保存。
- 错误展示具体影响、已保留内容与可执行恢复动作。阻塞操作的错误不可藏入折叠详情或只靠瞬间消失的 toast。
- 未保存切文件／离开保护、应急导出继续有效。本机浏览器范围明确，清缓存后的限制说明可在状态详情查看。
- 状态夹具可由公开数据与开发参数复现；故障注入不作为正常工具栏常驻选项，也不得在正式模式隐式启用。

## 6. 设计语言与 BoardUI 使用

- 为工作台建立集中设计规范：语义颜色、文字层级、间距、分隔、圆角、阴影、焦点、禁用与危险状态。使用 BoardUI 的语义 token、复合排版及 cx；引用对应实际组件路径。新增角色需在集中主题中定义，禁止页面散落硬编码配色与重复样式覆盖。
- 中文界面字体需实际检查；正文、辅助信息、输入框、公式和页码层次一致。课件原文不因应用主题重排或改色，页面内原字体不属于应用字号统一范围。
- 基础控件优先采用实际可用的免费 BoardUI 组件：先查目录，再取源码并核对许可／依赖。未取得 Pro 授权不获取 Pro 源码；不以购买 Pro 或配置 MCP 作为交付前置。
- 当前只读了 Button 的有限样式；扩展时扫描全部实际使用组件与类，防止生成 CSS 漏掉新控件。梳理局部实验 reader.css 的替换／保留范围，不叠第三套全局补丁。
- 不直接全项目 init，不把 Tailwind preflight 或工作台全局选择器泄漏到旧应用。若调整共享层，列影响范围并跑旧页面回归。标准 BoardUI 导入约定与局部路径适配有差异时记录原因并保持统一。
- 按阅读工具性质选择紧凑分隔与连续工作区，不把所有区域做成同权重大圆角卡片。强调色用于选中和主操作，减少无意义装饰。
- 微动效只服务面板、选择反馈和状态变化；采用官方 motion 规则，支持 prefers-reduced-motion。打开面板后的焦点与坐标在稳定布局下验收，动画不能成为定位漂移的借口。
- 开发范围内写入可持续生效的设计规则，避免后续代理另起视觉体系；保留现有规则其他内容。

## 7. 工程要求与入口

- 复用 FE-V01 的 PDF、坐标、批注和存储核心；样式和展示拆分为有职责的组件。ReaderLab 中状态编排若拆出，应说明旧逻辑与新调用的对应，行为改变另列，不混入无关重构。
- 真实阅读状态保持单一来源，目录、列表与助手不复制另一套页码／选区／批注状态。面板切换不重建整个文档或清空撤销栈。
- 使用独立工作台入口或在现有 reader 入口迭代，准确 URL 及启动命令写入报告。保留实验复现办法；默认课程入口保持可用。需要课程上下文的地方先通过明确标记的适配层留契约，不读取或改动正式 data。
- 本卡不新增正式模型调用、业务 API 或数据库迁移。静态演示资料与实际本机文件可区分；不得无提示自动打开私有资料。
- 读取器资源按需加载，避免默认课程页载入 PDF worker／整套阅读样式。缩略图应可取消过期任务，检查长课件和面板开关无明显资源堆积；无需为本卡建设大型虚拟化框架。
- 依赖固定版本并记录源码来源、许可证和修改；本轮不执行推送、发布或远端 PR 创建。
