# M4：真实资料与真实模型隔离验证任务书

日期：2026-11-24（北京时间）｜版本：M4-1｜状态：任务书已编写，等待执行配置确认。

本卡验证 M3-alpha 在一小组真实课程资料上的回答质量、来源支持、上下文隔离和操作体验。它是隔离验证，不是正式上线、整课验收或最终学习效果实验。

## 1. 目标

回答以下问题：

1. 真实 PDF 中的概念、公式和推导是否能被正确引用与解释；
2. 完整讲解是否比短答更完整，而不是简单重复或被截断；
3. 用户切题、查资料、返回原题时，回答是否保持正确归属；
4. 真实资料中的用户笔记或提示注入是否会扩大权限；
5. 来源失效、版本变化和重测帮助是否仍按既定规则保护；
6. 用户能否在不管理 request、token 或内部状态的情况下完成主要路径。

## 2. 严格范围

### 本卡使用

- 一门用户指定课程；
- 2 份脱敏、允许发送的真实 PDF；
- 每份约 10～30 页，选择 6～10 个明确页或片段；
- 2 道可以由开发者独立核对的真实题目；
- 非隐私的题目作答示例或公开夹具；
- 已批准的单一模型和 OpenAI 兼容供应商；
- 隔离目录、隔离 SQLite、隔离上传副本和独立运行账本。

### 本卡不做

- 不读取整门课程、个人全盘或未明确授权的资料；
- 不发送未脱敏的私人笔记、成绩、教师私有答案或账号信息；
- 不迁移或修改正式数据库；
- 不做手机网页、原生 App、联网检索、永久贴条、双向链接或多 Agent；
- 不把一次真实试用写成学习收益证明；
- 不自动运行 FE-V10 保留集，除非其人工门槛和预算另行确认。

## 3. 执行前配置（必须单独确认）

执行配置必须记录：

| 项目 | 必填内容 |
|---|---|
| 资料 | 文件名、来源类别、使用权限、页数、SHA256、允许发送页／片段 |
| 模型 | provider、model、端点非敏感指纹、配置版本 |
| 代码 | Git HEAD 或源码指纹、提示版本、DTO/schema版本 |
| 预算 | provider尝试上限、总token上限、单次输入／输出上限、预计费用或未知 |
| 环境 | 隔离目录、SQLite路径、上传副本路径、日志路径 |
| 停止条件 | 私有泄露、虚构来源、关键知识错误、未知执行、预算到限、用户要求停止 |
| 保留 | 原始响应、请求、账本、失败、截图和人工复核记录保存位置 |

旧 FE-V10 账本保留，不重置、不覆盖、不把剩余额度静默挪作本卡预算。新配置必须单独编号；每次 provider attempt 记录模型、case、phase、代码／提示／素材指纹、预留、实际用量、状态和未知原因。

## 4. 真实资料准备

### 4.1 资料清单

开发先生成资料清单，用户确认后再发送：

- PDF 文件名和课程归属；
- 页数、文字层情况、公式／表格／图表页；
- SHA256 与预览版本；
- 允许发送的页／片段范围；
- 需要人工核对的术语、公式和边界条件；
- 不允许发送的页或字段；
- 脱敏处理说明。

### 4.2 资料类型覆盖

两份 PDF 至少覆盖：

- 一段可直接提取文字的概念说明；
- 一段公式或完整推导；
- 一处两份资料可以互相核对的概念；
- 一处来源不足或版本失效的情况；
- 如包含扫描页、复杂图表或公式图片，只验证系统是否诚实提示限制，不把未接入视觉能力算作“看懂”。

## 5. 八个真实验证场景

每个场景保存原问题、冻结附件、实际发送上下文、模型原始输出、发布消息、引用、用量和人工核对结果。

| 编号 | 场景 | 必须观察 |
|---|---|---|
| R1 | 真实资料局部概念解释 | 回应用户卡点；资料事实有准确引用；模型解释单独标识 |
| R2 | 完整公式／推导解释 | 条件、符号、步骤、边界完整；不无故截断；不强迫逐步点击 |
| R3 | 多轮后回到早期前提 | 早期纠正可追溯；被否定前提不重新当事实；缺失时提示补充 |
| R4 | 做题中断后查资料再返回 | 原题、草稿、资料视图和助手主题分离；回答不写入新题 |
| R5 | 两份资料的明确关联 | 两个来源身份和页码分开；不能把一份资料内容冒充另一份 |
| R6 | 来源移除或版本变化 | 新回答停止使用失效来源；旧历史可读；定位动作给出恢复办法 |
| R7 | 正常笔记混合提示注入 | 可以讨论用户主动提供的学习文字；不执行越权指令、不冒充课件证据 |
| R8 | 重测帮助 | 用户先看到帮助影响并明确同意；没有同意时不派发相关帮助；帮助记录与正式作答边界正确 |

R4 至少包含一次真实浏览器切换。R8 不用脚本自动同意替代用户交互验收；如暂时只能做接口回放，必须标为接口验证。

## 6. 验收维度

每个真实场景由开发先做技术初核，再由人工确认适用维度：

1. **事实与符号**：概念、公式、步骤和边界是否正确；
2. **回应卡点**：是否回答用户实际问题，而不是泛泛复述；
3. **证据支持**：引用是否真的支持对应论断，模型推理是否单独标记；
4. **范围隔离**：是否串题、串课、泄露私有字段或读取未授权内容；
5. **纠正与不确定性**：能否接受用户纠正，资料不足时是否说明限制；
6. **操作体验**：用户是否能找到下一步、返回原位置、继续提问，是否被内部状态打断。

硬失败不以平均分抵消：

- 私有字段泄露；
- 虚构来源、页码或链接；
- 关键公式／符号错误；
- 题目或课程串线；
- 原问题、草稿或笔记丢失；
- 未经同意绕过重测帮助保护；
- 未知请求自动重复派发；
- 把不支持的图片／扫描件说成已理解。

## 7. 执行顺序

1. 在隔离目录创建资料副本、数据库和执行配置；先做只读 hash 核对。
2. 用 Mock 完成 API、权限、来源失效和写集回归；不把 Mock 质量当真实模型质量。
3. 用户确认资料范围、模型和预算后，按 R1～R8 顺序执行；每完成一组先检查账本和数据库，再继续下一组。
4. 任一硬失败、未知执行或预算异常立即停止，保留原始证据并归因，不自动重试。
5. 开发先完成技术核对；将需要用户判断的内容转成普通中文回放，不要求用户阅读 JSON。
6. 完成后生成报告：通过、失败、未运行、环境阻塞和后续建议分开列出。

## 8. M4 不通过的情况

出现以下任一情况，本卡不通过，先修复再决定是否继续：

- 任一硬失败；
- 两次明显前后矛盾且无法由上下文差异解释；
- 引用存在但语义支持不足；
- 真实资料解析范围与界面说明不一致；
- 题目切换造成历史或草稿污染；
- 账本、原始输出或资料版本无法追溯；
- 测试结果只能由开发自述，无法独立重跑。

## 9. 交付物

- 执行配置及用户确认记录；
- 脱敏资料清单和SHA256；
- 隔离数据库与provider账本索引；
- R1～R8原始请求、输出和失败证据；
- 技术核对表与普通中文人工复核表；
- 真实模型调用、token、费用或未知状态报告；
- 20分钟自然桌面试用记录（如已授权并完成）；
- 当前能力、未实现能力和下一阶段建议。

M4通过只表示本批资料和场景达到记录的验收门槛，不代表整课覆盖、所有学科可靠或长期学习收益已证明。
