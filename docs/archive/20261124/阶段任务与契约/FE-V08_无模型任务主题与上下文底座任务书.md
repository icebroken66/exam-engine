# FE-V08：无模型的任务、主题与上下文底座任务书

日期：2026-11-23｜版本：1.0｜状态：已获明确开发授权，工程实现与验收见实施报告，T20待用户反馈。

依据：[状态与上下文契约](../原始讨论与设计/学习Agent_状态与上下文契约草案.md)、[非线性场景表](../原始讨论与设计/学习Agent_非线性场景决策表.md)、[架构方向](../原始讨论与设计/多模态学习Agent_任务上下文与中断恢复设计草案.md)。本卡是契约建议的第一个有限实施切片，不代表整个 Harness 或多模态 Agent 已实现。原编写轮次不自动开工；2026-11-23用户另明确授权“按任务书开始开发”。实施结果见[实施报告](../实施验收与复核/FE-V08_实施与验收报告.md)。

## 1. 目标与范围

使用户在资料、题目和课程间自由切换时，系统能可靠保存多个学习事项与讨论主题，并明确选择本次提供给助手的内容。以真实服务端保存及不调用模型的上下文预览验证隔离、恢复与旧数据兼容。

| 本轮必须完成 | 后续阶段，不在本卡实现 |
|---|---|
| WorkItem事项、Topic主题、按主题草稿和确认上下文的持久化 | 真实生成请求状态机、专家调度及框架迁移 |
| 多个未完成事项，暂停／恢复不改正式学习状态 | 多个正式当前题、旧题重新开放作答、新评分规则 |
| 助手内主动取材及附件预览／移除／替换 | 照片上传存储、OCR／视觉识别、纸稿转录与版本分析 |
| 资料选区、公开题目、明确选择的草稿、已提交作答／可见反馈绑定 | 普通聊天读取教师参考答案、自动读取所有笔记 |
| 无模型ContextManifest预览与纳入／排除追踪 | 模型发送、联网检索、真实证据研究、自动笔记／双向关联 |
| 旧助手schema1只读映射／显式复制及旧入口兼容 | 全量自动迁移、云同步、多用户、手机网页 |

新功能界面明确“上下文准备，尚未发送 AI”。不得把固定回复或通过预检显示为模型理解。当前旧题内带学如保留，仍通过原入口／原规则执行，不纳入新底座真实发送；本卡新路径不能调用它或触发其帮助记账。

## 2. 开工前检查与结构

- 核对当前FE-V06／07实现、最新反馈及仓库指令，记录HEAD、工作区差异和前置源码指纹；保留所有未提交改动，不把旧main当完整基线。前置用户评审状态不自动改为完成。
- 先交付对象／命令映射、候选端点、持久化方案和一份公开JSON，再分块实现。复用现有FastAPI／SQLAlchemy／SQLite、模型和前端壳层，不引入Agent框架或多自治进程。
- 建议独立assistant workspace领域模块／路由与前端状态适配；不要将全部功能继续堆入App、LearningPanel或现有schema1快照PUT。正式学习、阅读和Topic各有唯一状态源。
- 若新增表，说明唯一约束、课程归属、索引、迁移／回退和课程删除处理。create_all只可用于新表创建，不能冒充已有字段迁移；仅临时库先验证，不自动修改正式库。

## 3. 数据与行为契约

### F1：学习事项，不复制正式业务真值

- 支持platform_task（引用既有session／task）、exploration（明确概念探索），可同时保存多个。外部纸题可预留类型但本轮不展示不可用创建入口。
- attention首版为ongoing／paused；独立探索可显式finished，平台题不提供伪正式“完成”按钮。正式stage、当前题、能否提交／带学均从原服务投影读取。
- 同课程同平台任务建立事项幂等，不因刷新／重复点击新建多份。课程名／题名仅展示，ID绑定；同题跨会话需按真实task区分。
- 暂停／恢复只更新事项及恢复书签，不改current_task_id、stage、Attempt、帮助或成绩。已推进旧题恢复为历史查看，显示不可正式作答原因，不擅自重开。
- 普通导航、浏览时间和独立概念提问不强制创建新事项；保留原未完成项，目标不明确时允许不绑定。

### F2：主题、草稿与并发

- 支持single／independent主题；compare可通过用户明确选两项创建验证主题，附件按目标分组，不扩展成复杂主题管理器。主题属于一个课程，首版不支持跨课比较。
- 同一应用级助手显示当前主题名称、关联事项和可辨认的上下文摘要；提供新主题、主题切换、返回事项和恢复列表。无需用户管理技术ID。
- 每主题独立保存文字草稿、确认绑定列表及context_revision，用户可在同一主题连续准备问题；本卡不新增生成消息或发送后历史。已有schema1提问记录保留历史身份。
- Topic revision用于并发，context_revision只在上下文绑定／范围改变时递增；仅正文改变不伪造附件变动。服务器回执后才显示已保存。
- 显式写命令带command_id／expected_revision；相同ID相同载荷重放返回既有结果，相同ID异载荷409。SQL条件更新／唯一约束保护两窗口，不能用前端读后写冒充原子CAS。
- 存储失败保留内存与导出，冲突停止覆盖，提供显式重读和当前数据导出。切课保留未保存内存；硬刷新前未保存内容不保证，界面说明范围并沿浏览器允许的离开提示处理。

### F3：助手内主动取材

- 助手输入区提供“添加上下文／从工作区选择”。点击进入临时取材模式，中央明显显示；支持资料选字／区域，以及公开本题、当前草稿、已提交作答／已显示反馈的明确选项。
- 选区后先预览目标、页／题、文本或区域图示，再确认绑定；有旧绑定时明确新增还是替换。为控制范围，最多4个绑定，每绑定最多20个区域，每条文本上限10000字符；为本卡工程限额，不宣称模型容量。超限提示，不静默截断。
- Esc／取消恢复原工具与先前选区，旧草稿和已确认绑定不变；取材不创建个人高亮或贴条。个人涂写、框选、高亮、答案勾选不改变助手绑定。
- 当前正式作答草稿仅用户明确选择时复制，标“未提交”；后续修改原答案不会更新已附带快照，可显式重新取材。不读取所有sessionStorage／个人笔记。
- 资料绑定存source ID／原件hash／preview版本／页／区域／精度和用户片段；题目／答案由服务端校验公开范围。客户端草稿是用户声明，不作为已提交答案。
- 区域绑定本轮只验证定位和范围，预览不得声称已识别文字或看懂图片；不调用OCR／模型，不把坐标冒充视觉内容。
- 中央旧“向助手提问”快捷入口如保留，只打开同一助手取材预览，不能绕过确认或另存阅读器私有对话。

### F4：视图与恢复

- 当前中央页面、所选主题、草稿上下文分开。展开课程树、打开资料、翻页及停留不自动修改事项attention或附件；同课切页保留主题。
- 按明确关联入口去资料可记录origin／target书签；手动切资料只记视图，关系unknown，不猜原题已暂停。
- 返回恢复有效题目／资料身份和已保存位置；正式草稿沿原标签页保障，不能声称新增了服务器草稿同步。需要离开未保存阅读器／贴条时先执行原保护，不能强制卸载。
- 切课程恢复目标课主题和本机焦点偏好，A课延迟响应不能覆盖B课；课程身份是权限边界。恢复已失效来源／任务时显示历史或重选，不按名称匹配新文件。
- 首版一个返回点可接受，但关系记录带明确目标，不把数据结构锁为所有学习必须按栈原路返回。

### F5：无模型上下文包

- 提供“检查本次上下文”只读操作，输入topic／context revision及问题文字，输出Manifest预览。它不是SendRequested，不创建Request运行状态，不保存机器人消息，不调用网关。
- 返回课程／主题／事项、明确目标、确认附件及当前有效版本、纳入与排除条目及理由、可见性／能力限制。读取问题可无附件，不能强制概念问题先选资料。
- 本卡不检索整课，不用模型判断指代；目标可能冲突时显示needs_context_choice及明确候选，不假装已理解意图。不通过前端当前视图默认读取全部内容。
- 新题默认排除旧题答案／照片／局部对话；compare明确选择后按题分组。历史主题可在列表中看，但不全量加入Manifest。
- 主题／绑定revision过期返回context_stale；来源移除、hash变更、页码越界、题目非当前及反馈可见性不满足时逐项报告，不能静默换用新内容。
- 隐藏reference_answer／rubric／analysis不进入普通Manifest及trace。已显示反馈以权威已提交记录取值，客户端标成answer不等于有权限读教师字段。
- 预览页只展示用户可见trace，不暴露内部路径／私有字段；无思维链。预览不改updated_at／attention／学习事件；必要HTTP访问日志不算业务写入。

## 4. 候选接口与保存边界

采用独立版本路由，例如/api/courses/{course}/assistant/v2；准确端点与DTO在首轮交付说明中固定，并保持原schema1接口兼容。最少包括：

| 操作 | 输入与输出约束 |
|---|---|
| 分页列事项／主题及读取单项 | 课程过滤、revision、公开业务投影；只读不隐式创建 |
| 显式建事项／主题、暂停／恢复 | command_id、expected_revision、目标引用，返回实际状态 |
| 读取／保存composer | 主题revision、文字、绑定ID、context_revision；不允许写assistant/tool角色 |
| 确认／移除／替换绑定 | 明确目标、角色、资源版本和确认行为；事务更新composer上下文 |
| 预览Manifest | 指定topic/context版本和问题，无生成副作用 |
| 读取旧记录、显式复制到新主题 | 源指纹＋command_id，保留legacy标识，不静默上传本机内容 |

本卡不实现assets图片上传、requests真实生成、专家工具、save-artifact接口；不让这些未来端点返回伪成功。

数据结构需有schema版本、长度／条数上限、稳定ID及受控枚举。分页默认20／最大50；草稿10000字符；不放宽原服务现有资源限制。数量上限与错误提示记入DTO和测试。归档课程可读只读，新增修改拒绝；来源移除保留历史不可新绑定，课程永久删除处理本卡记录，不遗留孤立可访问数据。

## 5. 旧记录兼容与上线边界

- schema1本机／服务端会话继续读取、导出及原保存；新模型不通过改旧schema号强行解释。旧context视作历史关联，不自动当本次附件／授权。
- 用户显式选旧记录可复制到新主题草稿，显示来源和未发送状态；默认复制文字，重新附带历史上下文需单独校验确认。相同命令重试不重复导入，不覆盖非空新草稿。
- 本机记录不自动上传，旧TutoringTurn／UsageRecord／ReaderSnapshot不改写。原题内带学如保留，UI区别本卡“上下文准备”，不要让用户误以为新按钮可发送。入口替换不能让已存内容消失。
- 新表／字段给出可复现迁移与临时库演练；保留未知schema原记录并可导出。回退关闭v2新写入口、保留新记录只读／导出，不删除用户数据或批量清空存储。
- 通过功能开关／独立适配逐步接入已有壳层，说明本机与服务端模式支持矩阵；首版新底座采用服务端保存即可，本机旧模式保留，不额外实现第二套v2本机事务。服务不可用时明确失败，不暗中切换存储。

## 6. 场景覆盖与验收

真实Edge／Chrome，1024×768、1440×900、1920×1080；关键取材与开合测125%浏览器缩放。Mock仅作数据及能力夹具，不得实际调用mock网关来伪装无模型。

| 编号 | 场景 | 必须观察到 |
|---|---|---|
| T01 | 同课程建立多事项、独立探索、暂停恢复 | revision可靠，原LearningSession/current_task/Attempt/帮助不变；普通导航不强制建事项 |
| T02 | 已推进旧题恢复与非法task引用 | 历史可看但不重开作答，课程归属与实际能力正确 |
| T03 | 新主题、切主题、跨课程再返回 | 草稿／确认附件分别恢复，焦点偏好不污染权限，未保存内存受保护 |
| T04 | 资料取材确认、取消／Esc、普通高亮／勾选 | 仅确认后更新绑定，取消不留笔记，普通操作不附带 |
| T05 | 明确附带草稿与已提交反馈 | 未提交／已提交区分，服务端公开数据准确，隐藏教师字段不泄漏 |
| T06 | 改答案／翻页／换文件后查看已绑定快照 | 不自动跟随替换，可显式更新；过期信息可见 |
| T07 | 新题Manifest与显式两题比较 | 前者无旧题私有输入，后者按题分组，无跨课内容 |
| T08 | 无附件概念问题与有歧义目标 | 无附件可预览；冲突提示选择，不偷读当前页／草稿 |
| T09 | 来源移除／hash或preview变更、越界、归档 | 准确失效／只读，不静默迁移／重新授权；旧历史保留 |
| T10 | 两窗口同topic写入、绑定和草稿竞争 | 服务端CAS及context_revision有效，409保留本地内容，不丢已确认绑定 |
| T11 | 同command_id重放／异载荷与丢回执 | 同载荷不重复事项／主题／复制，异载荷冲突，重读不写 |
| T12 | 保存失败／超时／服务重启与全新浏览器读取 | 真服务端已存状态恢复，失败不报成功，当前未保存内容可导出／显式重载 |
| T13 | 慢请求时切课／切主题 | 旧响应不覆盖新目标，原主题可找回，视图不抢焦点 |
| T14 | 旧schema1／未知schema、显式复制 | 原数据不覆盖、不自动上传，不冒充生成消息或有效附件 |
| T15 | 长间隔、纸上作答无消息、只翻页 | 无自动完成、评分、导航诱发模型调用或帮助记录 |
| T16 | 上限、角色伪造、坏区域、跨课ID | 受控错误、无截断假成功，不接受伪造assistant/tool状态 |
| T17 | 真实原临时API联通及两浏览器路径 | 不是共享缓存冒充持久化；读操作无业务写副作用 |
| T18 | 桌面尺寸、键盘／中文输入、取材定位 | 控件可达，确认取消焦点合理；原笔记／橡皮擦及≤4 CSS px定位不退化 |
| T19 | 迁移／回退、原学习与助手回归 | 旧记录和既有帮助保护保持，原带学运行锁不被绕过 |
| T20 | 用户试用：做题→查资料→独立主题→恢复 | 目标和附件区别易理解，不强制线性流程；记录实际反馈，未反馈标待反馈 |

至少用两个课程、两道不同数字／题干的题、同名不同内容资料、不同页选区作为污染夹具。检查数据库前后与网关spy：预览、取材、事项命令不得新增Attempt、LearningEvent、TutoringTurn、UsageRecord或模型请求；允许的写入仅本卡显式领域对象及composer。

覆盖S01～S10、S11等待语义、S16／S17上下文元数据、S20失效、S24绑定纠正；只验证其中本卡边界。S12～S15真实图片理解、S18／S19真实生成、S21帮助合流、S22评分核查、S23产物写入、S25专家预算不算本卡完成，必须在结果中标后续而非已验证。

建议实现顺序：先后端身份与CAS／兼容 → 前端主题／草稿及恢复 → 助手内取材与绑定 → Manifest预览与隔离故障测试 → 用户评审。每步可核验，实际实施不得自动进入真实发送。

## 8. 完成判定

T01～T19及受影响工程检查通过，T20用户评审完成后才能标已完成；工程通过而无反馈标待验收／待反馈。跨课／跨题污染、未授权附带、丢草稿、虚假保存、教师字段泄露、改正式任务、自动模型调用、旧数据覆写为阻塞。

本轮结束停在无模型底座。下一阶段另写请求生命周期与教学适配任务，评估幂等／生成恢复及真实帮助边界，不自动新增代码、调用真实模型或引入多Agent框架。
