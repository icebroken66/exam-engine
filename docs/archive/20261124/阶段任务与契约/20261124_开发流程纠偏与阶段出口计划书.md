# 开发流程纠偏与阶段出口计划书

日期：2026-11-24  
适用项目：学习工作区／资料阅读／AI 学习助手

## 1. 目的

本计划用于解决开发过程中反复停顿、重复验收和范围不断扩大的问题。它只调整开发组织方式，不缩减产品设想，也不取消资料内学习、批注、题目关联、多模态输入、跨资料解释和 AI 返回界面等长期目标。

当前产品仍以以下方向为长期约束：

- 电脑网页是首要平台，手机网页后置；
- 资料是可学习的内容，不只是生成题目的附件；
- 用户可以在资料上阅读、批注、记录思考，并与题目和 AI 解释关联；
- AI 助手服务于题目、资料和一般知识学习，不局限于题目解析；
- AI 必须理解用户在资料、题目和中断恢复之间的上下文；
- 真实资料、图片、纸笔和多模态能力属于后续产品目标，不能因为当前切片未实现而被视为取消。

## 2. 当前状态

### 已完成或已达到阶段出口

- M3-alpha：短答／完整讲解、续问关系、上下文冻结、题目／资料隔离和预算预检已完成隔离工程复核。
- M4：公开合成 PDF 与真实模型的隔离工程验证已完成；来源身份、页码、哈希、引用审计和隔离数据库审计通过。

### 尚未完成但不应继续扩大当前阶段

- 浏览器人工体验；
- 真人逐维语义评分；
- 真实课程资料验证；
- 原生 125% 缩放、完整 Tab／IME、PDF 像素级渲染和复杂迟到事件。

这些项目保留为“体验／质量待验证”，不再自动阻塞已经通过的工程切片，除非它们直接破坏下一张卡的核心行为。

## 3. 三条独立工作轨道

### A. 工程轨道

负责代码、接口、状态、来源、引用、错误处理、回归测试和构建。

出口只能是：实现完成、工程验证通过、工程阻塞。

### B. 产品体验轨道

负责浏览器操作、布局、可发现性、键盘、缩放、中文输入和真人试用。

出口只能是：体验通过、体验待验证、体验阻塞。体验待验证不等于工程失败。

### C. 模型质量轨道

负责真实资料、真实模型、回答完整性、引用正确性、澄清行为和语义质量。

出口只能是：模型验证通过、模型质量待人工复核、模型阻塞。

三条轨道分别记录证据，不把其中一条的结果改写成另一条的通过结论。

## 4. 每张开发卡的固定边界

每张卡必须在开始前写明：

1. 一个用户问题或维护问题；
2. 本卡目标；
3. 交付文件和影响范围；
4. 3～5 项验收点；
5. 明确不做的内容；
6. 依赖和风险；
7. 完成后的阶段出口。

开发开始后，验收点冻结。发现新问题时，只能归入以下三类：

- 直接阻塞本卡：本轮修复；
- 不阻塞本卡但需要处理：进入下一张卡；
- 体验或模型质量问题：进入对应并行轨道。

没有直接阻塞关系的新要求，不得追加到当前卡。

## 5. 复核规则

复核者每轮只输出四部分：

- 已通过项；
- 最多三个阻塞项；
- 非阻塞的待验证项；
- 下一批次建议。

复核不重新设计整套产品，不代替用户完成视觉签收，不代填真人语义评分，不为了凑预算增加真实模型调用。

开发修复时必须保留原始失败证据、unknown 记录、旧账本和用户数据；修复记录应说明改动文件、回归命令、未覆盖内容和风险。

## 6. M4 收口规则

M4 当前归档为：

- 公开夹具真实模型工程验证：完成；
- 来源与引用隔离审计：完成；
- 浏览器人工体验：用户选择跳过，未验证；
- 真人逐维语义评分：未执行；
- 真实课程资料：未验证；
- M4 整体产品签收：暂缓。

不再追加公开夹具调用，不修改旧 FE-V10 账本，不把隔离 API 回放写成浏览器人工体验。

## 7. 下一批次安排

下一批次只选择一个主目标，优先顺序如下：

### 首选：现有真实输出的普通中文语义复核

只复核已保存的 15 次 M4 输出，不调用新模型。开发初核已记录在[普通中文复核记录](../实施验收与复核/20261124_M4公开夹具普通中文复核记录.md)；真人逐维评分仍未执行。记录回答是否完整、是否正确引用、是否正确澄清、是否错误跨题承接。结果进入模型质量轨道。

### 备选：真实课程资料准备

仅在单独明确资料范围、模型、预算、脱敏方式和停止条件后执行。不得自动使用个人资料，也不得复用公开夹具的预算授权。

### 并行质量项

可以单独建立一个桌面体验卡，处理 125% 缩放、Tab／IME、PDF 像素或迟到事件中的一项；每次只选一项，不重新打开 M2 总门槛。

## 8. 任务完成定义

一张卡只有在以下条件满足时才写“完成”：

- 目标范围内的代码或文档已交付；
- 验收点有对应证据；
- 未完成内容已单独列出；
- 未验证项没有被写成通过；
- 不存在未说明的直接阻塞问题；
- 下一张卡可以在已知边界内开始。

“工程完成”“体验通过”“模型质量通过”“产品整体签收”四个结论必须分开记录。
