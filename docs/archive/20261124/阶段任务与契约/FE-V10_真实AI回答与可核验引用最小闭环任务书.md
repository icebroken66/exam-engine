# FE-V10：真实 AI 回答与可核验引用最小闭环任务书

日期：2026-11-23。状态：用户已授权继续开发，工程实现与隔离Mock验收通过；真实模型评测及本人体验待验收，不操作正式库。

## 1. 目标与完成含义

让用户在现有统一助手中，明确附带课件文字或题目，直接提问，得到围绕该上下文的真实回答，并能点击引用返回资料页或对应题目。用户可随时阅读资料、切换页面或暂时离开，回答仍归属原讨论，不丢稿、不串题。

本卡验证“能否给出可核对、范围正确、回应卡点的学习帮助”，不是仅把发送按钮接通，也不宣称已经实现完整多模态 Agent 或证明学习收益。保留 Harness 管理状态与权限、统一导师负责交流、专家按需接入的方向；首版执行一个导师，不建立多个常驻 Agent。

## 3. 范围与明确后置项

### 本卡必须交付

1. 同主题连续文字对话，包括无附件但表达清楚的独立概念提问。
2. PDF可提取文字页的明确片段取材、服务端证据核验与页级引用返回；已有PPT导出PDF按同一能力处理，不承诺原生PPT解析。
3. 已有四类题目附件：公开题干、未提交作答快照、已提交作答、已显示反馈；保持角色、题目和版本身份。
4. 同题追问、资料往返、明确两题比较的上下文隔离；比较中每题分别校验帮助条件。
5. 请求冻结、持久化消息、幂等、停止展示、失败恢复、刷新重读、来源失效检查。
6. 一组固定问题材料、工程验证、有限真实模型评审和一次本人短试用，分别给出结论。

### 本卡不交付

- 手机网页、原生App、界面整体重构。
- 纸笔照片、OCR、图表／扫描PDF视觉理解、自动PPTX转换。
- 全课程或跨资料自主检索、互联网搜索／网页引用、向量库和知识图谱。
- AI自动在资料上写贴条、建立永久双向知识链接或修改用户笔记。
- 多专家并行、递归委派、任意代码／shell执行、长期记忆及全自动学习规划。

长期“在另一页／另一资料找依据、在中心区展示讲解、保存贴条和双向链接”的需求保留。本卡先打通有效引用→用户点击定位；不把后置需求改写为取消，也不显示尚未实现的入口。

## 4. 用户流程与交互要求

### 4.1 提问与回复

用户直接输入问题，可在助手内添加内容；普通高亮、自由笔刷、阅读停留和中央作答不自动作为附件。发送前自动完成必要保存，冻结本次输入；保存失败则不调用模型，正文和候选保留。

发送成功的判断是服务端已接受并返回可恢复request_id，而非模型已回答。客户端在请求前生成稳定request_id；接收响应丢失时，以同ID查询／重放接受请求确认，不能换ID重新生成。输入框在确认接受后仅清除本次冻结的文字；发送期间新增输入另存，不被旧回执清空。

回复以正常消息显示，可含简洁分段、必要公式、例子与一个自然追问；避免每次固定长模板、长计划或完整流程。用户只问一个词时优先回答该词；用户指出解释不对时明确修正前提，不循环复述。

### 4.2 状态与操作

正常界面仍以消息、输入、添加内容、发送为主。生成中在本条请求附近显示真实状态和“停止”；错误时就地显示可用恢复动作；技术Manifest、模型、revision、费用明细进入诊断或适当详情。沿用现有BoardUI和语义样式。

首版采用“生成完成→校验→整条发布”，不展示未经核验的流式正文，也不伪造思考过程。发送快捷键沿既有Ctrl／Cmd+Enter，中文输入法组合状态不误发。未配置模型／只读课程／预算不足时解释原因，不永久显示已接通的假能力。

### 4.3 资料、题目与视图切换

- 视图焦点与讨论目标分离；切到资料不代表放弃原题，停留时长不改变目标或触发生成。
- 生成期间翻页、关闭助手、打开另一主题不清空请求；结果写入原Topic，不抢焦点、不自动跳回原页。
- 换题附件沿FE-V09的明确选择；两题比较按事项分组，不能把第二题答案当第一题背景。
- 引用由用户点击后跳转。跨视图前保护未存正文和笔记，保留返回原学习位置的路径；不得擅改current_task_id或学习阶段。
- 请求执行中允许编辑下一条草稿；同Topic首版最多一个非终态请求，不开放并行发送。

## 5. 上下文、证据与来源契约

### 5.1 输入范围

每次请求冻结课程、Topic／事项、用户正文、明确附件ID及其版本、允许历史范围、相关公开题目指纹与帮助策略。实际输入由服务端构建，不接受客户端传入system／assistant消息、教师私有字段或任意工具名。

默认只读取同Topic已发布历史、本次正文、确认的有效附件；不读取别的Topic、课程、旧带学记录、未确认笔记和屏幕草稿。后续移除附件后，新请求不能靠历史消息夹带被移除附件的原文；历史依赖该附件的内容应排除或脱敏并记录原因，历史界面仍保留真实记录及失效标记。

同Topic历史先不做模型摘要：最多最近6个完整问答对，且服从总输入预算；不拆半个问答对，不静默截断附件或用户当前问题。因范围／预算排除时给出简短提示及诊断记录。明确比较最多两事项。

### 5.2 PDF证据核验

服务端读取已确认PDF页，校验course_id、source_id、原件hash、预览版本与页码，提取带来源信息的文本。可在文字可匹配时生成有界相邻句背景，需在取材预览说明实际包含范围；不偷偷扩展到整份资料。

客户端选文必须能在服务端提取文本中经过确定的空白／断行规范化后匹配，才可标为verified_source_text。保留原始文本、规范化规则、页内证据片段及指纹。多个同文命中或无准确坐标时只能页级定位，不能伪造精确框选。

无法匹配时，允许用户显式选择“作为我提供的文字继续”，标user_provided_text，不能引用成PDF原文；或者提示重新选取／改用可提取文本页。纯区域、扫描页、图表或公式提取明显不完整时告知本卡不支持，不声称看懂了图片。

### 5.3 引用输出与核查

服务端生成有界Evidence列表：evidence_id、kind、source／task／attempt身份、版本、页码／区域精度、原文或快照、provenance。模型只能引用列表内ID；服务端将ID解析为动作，模型不得自造文件路径、页码、课程ID或可执行URL。

| 来源类型 | 用户看到的含义 | 允许的定位 |
|---|---|---|
| 已核验课件片段 | 来自《文件名》第N页 | 打开原件有效版本对应页；精确区域有证据才临时标示 |
| 公开题目 | 本题题干／选项 | 打开对应题目或只读历史，不推进任务 |
| 学生／已提交作答、可见反馈 | 你的作答／已显示反馈，不能作为理论正确性的证明 | 打开对应公开记录；未提交快照不冒充Attempt |
| 模型补充解释 | 模型补充，未经外部资料核验 | 不伪造来源，不加虚假引用按钮 |

无附件的常识性概念可给有边界解释，但不得编造论文、网址、页码或宣称来自课件。要求严格原文依据而现有证据不足时，明确不足并请用户补材料。

回答结构至少含reply文本及claims／citation绑定，区分哪些解释由哪个证据支持，避免只在末尾堆引用。确定性校验负责ID、版本、归属、引文匹配、动作白名单；“证据是否真正支持论断”另做人工评审，不能把ID存在称为事实核查完成。无效引用回复不发布为正常完成，保留草稿与可理解错误；不自动追加昂贵修复调用。

点击引用时重新校验归属与版本：来源移除／版本变化提示失效，不跳到同名新文件，不修改笔记。临时定位标记可关闭，不作为ReaderSnapshot永久批注保存。

## 6. Harness、工具与教学适配

执行顺序：接收并持久化意图→校验版本及权限→确定性证据准备→必要澄清／帮助同意→导师一次生成→输出校验→原Topic发布→用户点击引用定位。简单问题不强迫经过澄清或长流程。

最小工具能力清单：

| 能力 | 输入边界 | 行为与禁止项 |
|---|---|---|
| 读取确认上下文 | 服务端验证的Topic及binding IDs | 只读已授权快照，不扫描全课程 |
| 读取课件证据 | 已授权source版本、页及片段 | 有界文字提取，不读任意本机路径／URL |
| 读取公开题目投影 | 已验证session／task／attempt | 返回可见字段，拒绝教师私有答案进入通用上下文 |
| 构建／校验引用动作 | 本次Evidence ID | 返回有类型的导航动作，不直接操作DOM或写笔记 |

这些能力首版可由Harness确定性调用，无需把工具选择都交给模型。扩展接口保留来源与预算记录；本卡不为未来专家一次建齐所有表。资料中的“忽略规则、读别课”等文字只是待学习数据，不能改变scope或执行权限，需有对抗回归。

### 教学与独立重测边界

- 通用导师默认只取得用户可见题目及明确附带内容；若专用教学适配确需教师上下文，只在原权限检查后给对应执行角色，不在通用Manifest／GET／日志中泄出。
- 已关联平台题目的解释走既有帮助许可、running互斥、发布／曝光与独立性保护；用户需要同意时，用自然语言一次说明，不回退旧带学模式开关。
- 新request与旧TutoringTurn／帮助事件建立稳定映射，只允许一次模型派发、一次对应帮助记录及正确用量归属；不能同时调用旧send和新网关导致双回答。
- 比较两题时各自校验；任何一题未满足条件都先说明并等待，不用部分授权生成整段答案。正式提交／推进仍按原业务校验，不能仅锁Topic。
- 关联题目时不因声称“只是问概念”就绕过原许可；纯无关联概念不默认计帮助。无明确附件却指向“这题／上面”的问题先要求明确对象；不根据当前屏幕自动附带内容。无法保证识别用户未透露的场外题目关联，应如实说明能力边界。
- 若适配未通过，本题真实发送保持禁用并显示原因；独立资料／概念子路径可工程验证，但整卡不得标全量完成。

## 7. 请求、幂等、停止与持久化

沿状态契约使用accepted、waiting_input、queued、preparing、running、validating及终态published／blocked／failed／cancelled／stale，另保留cancel_requested与interrupted_unknown表达未知窗口。不得把浏览器断网当作模型未执行。

候选接口位于现有v2下，开发第一步锁定DTO和兼容说明：

| 操作 | 最小责任 |
|---|---|
| POST /topics/{id}/requests | request_id、Topic/context版本、正文／确认binding IDs；冻结意图与payload_hash，接受回执可恢复 |
| GET /requests/{id} | 只读状态、公开错误、消息／引用与用量边界；重读不生成 |
| GET /topics/{id}/messages | 有序分页，同请求不重复，客户端不能写assistant角色 |
| POST /requests/{id}/resolve | 有版本的澄清／本请求许可；目标实质改变则另建请求 |
| POST /requests/{id}/cancel | 幂等停止／取消回执；说明派发后上游可能仍执行或计费 |

必须满足：

1. 同request_id同规范载荷重放返回原状态；不同正文、附件、Topic或版本返回冲突。双击、超时和刷新不新增模型调用。重新生成必须用户明确操作，以新ID及retry_of记录。
2. 请求接受与冻结记录短事务提交，再异步执行；不在长模型调用中占用SQLite写事务。明确首版单API进程／有界worker容量，不宣称多实例exactly-once。
3. 供应商派发超时、进程在派发窗口重启等情况不能确认执行时进入unknown；读取、轮询、自动恢复不重新派发。核查ModelGateway及provider下层自动重试，不能仅在外层设置single_attempt就宣称无重复计费。
4. 发布前重新检查来源有效性、权限、任务内容与帮助基线。请求自身帮助事件引起的进度变化可有据识别；不能忽略所有version变化。来源失效则不发布为有效新答案，保留审计和费用。
5. 派发前停止不调用模型；派发后停止阻止未发布正文继续发布，迟到结果不能出现到当前新主题。已有帮助记录不因停止抹除，不承诺退款。
6. 关闭／刷新后凭服务端消息与请求恢复，不靠组件内存伪装持久化；上一请求回执不覆盖下一条草稿。课程归档禁止新请求，历史按现有只读规则保留。
7. 重试、失败、取消、未知和实际用量均可追踪；请求终态、消息和帮助映射保持一致。可恢复错误不丢正文、附件或已发布历史。

## 8. 首版容量与费用边界

以下是保守工程上限，不是延迟／质量承诺；实施时集中配置，可因测量降低或调整，但必须在真实评测前记录版本：

- 复用最多4个确认附件、每项最多10000字符、比较最多2事项的既有边界。
- 用户当前问题沿10000字符上限；整包输入另设12000模型token硬预算，输出最多1500模型token，单次provider等待上限60秒。无法可靠预估token时采用保守估计／拒绝策略，不宣称估计精确。
- 同Topic最多1个非终态请求；单API首版最多2个运行请求、有界等待队列最多4个；超额立即返回可理解的忙碌提示，不无限挂起。
- 每用户发送首版最多1次导师派发、无专家调用／模型自动自修。超长先减少最旧完整历史；仍超限则提示缩小问题或附件，不能静默丢弃当前输入。
- 调用模型使用现有服务端配置与预算，不在任务书硬编码供应商型号或价格。费用未知时写未知，不把未配置价格的0当作免费。

真实评测前填写一页执行配置：供应商／模型及版本、公开或授权材料范围、最多36次provider尝试（含失败）、每次token限额、总token或金额硬上限、允许网络及停止条件。金额上限／总token预算、实际模型未确认前只跑Mock；本次“设计任务书”不授权付费调用。需要确认时应先备好可审阅材料与执行配置，再一次性确认，不在普通阅读／提问操作中反复询问。

### 10.2 固定材料与真实回答质量

沿用evals/tutoring的证据管理方式，可建立本卡子目录但不替换既有评分历史。准备18项独立场景：12项开发／回归、6项保留。材料至少含可提取文本PDF、两道有可核查依据的题目、一个教师私有字段对抗夹具。每项包含原问题、可见证据、正确解释要点、禁止泄露内容、预期引用／澄清及允许业务变化；不得只写“回答合理”。

开发集覆盖：独立概念、片段解释、同题追问、反馈解释、纠正先前误解、资料往返、目标歧义、明确比较、证据不足、来源失效、提示注入、重测帮助。工程故障用确定性夹具，不浪费真实模型调用反复测试断网。

保留集6项在完成策略后运行，每项独立上下文重复2次，保留12个全部输出。保留题一旦用于调提示／实现，就转为回归；若要继续声称未见效果需另准备新保留题并重新预算。无必要不比较框架或多种模型，不以最好的一次代表稳定性。

人工按以下维度分别打0／1／2分，模型打分只能辅助：事实与关键符号正确性、是否回应实际卡点、证据能否支持对应论断、上下文范围、纠正／不确定性处理。2为满足、1为局部不足、0为明显失败；逐维保留理由与原件定位。

本卡真实能力门槛：

- 所有工程验收通过；真实输出零跨课／跨题私有内容泄露、零虚构来源、零未授权解法曝光、零关键知识错误。硬失败不能用平均分冲抵。
- 开发集每项最终通过；保留集12个输出均无硬失败，至少10个在所有适用质量维度均为2，其余每项不得出现0分。任一场景两次明显矛盾即作为不稳定问题记录，不择优。
- 本轮所有出现的引用链接均能有效返回正确对象；页级精度可接受，不能冒称精确文字位置；人工逐条核对支持关系。
- 报告首次可见状态、端到端延迟、调用数、实际用量／未知费用、失败及重试。60秒上限按配置执行；未知执行必须正确呈现。小样本不据此宣称生产延迟分位数或学习增益。

### 10.3 本人短试用

安排一次约20分钟的桌面学习：读资料问概念→围绕题目追问→去资料查阅→回原讨论→点击引用核对。由用户按自然节奏操作，记录必须有人解释才能继续的地方、错归属、系统纠正次数及引用是否有帮助。

主要任务均应能独立完成；任何丢稿、串题、错误定位、强迫理解技术模式均为失败。用户不满意如实登记，修复后验证；不以自动化通过替代本人认可，也不因一次觉得有帮助就宣称学习有效。邀请他人另需明确授权。

## 11. 交付物与收口

必须交付：最小实现、定稿DTO／数据迁移与回退说明、可重复工程及浏览器脚本、固定材料与rubric、真实运行配置／原始输出／用量、失败归因与修复记录、本人试用结论、当前能力说明。私有原件、数据库、密钥与完整个人对话不入库，证据脱敏并说明存放位置。

报告分开标记“工程通过／真实模型质量通过／本人体验通过”。未做真实调用只能称工程准备完成；未做题目教学适配只能称资料子路径完成；未获本人反馈仍待体验验收。全部门槛满足方可标整卡完成。

完成后只提出下一步建议，不自动开始图片理解、课程检索或多专家。在真实失败证据中选择最影响学习的一项，再决定下一卡；长期多模态与跨资料定位目标持续保留。
