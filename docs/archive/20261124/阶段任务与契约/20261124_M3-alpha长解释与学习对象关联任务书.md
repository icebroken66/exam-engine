# M3-alpha：长解释与学习对象关联最小实现任务书

日期：2026-11-24（北京时间）｜版本：alpha-1｜状态：任务书已编写，等待开发执行。

本卡承接M2已确认的核心设计边界，目标是实现一个可运行、可回放的最小学习帮助闭环。它不追求一次完成完整多模态Agent，也不把M2剩余视觉矩阵重新变成开工阻塞。

## 1. 目标

用户能够在电脑网页中：

1. 针对资料或题目提出短问题，得到清楚的短答；
2. 明确要求完整解释时，在可阅读区域查看一段较长的结构化讲解；
3. 查看已生成内容、核查来源、定位资料页并返回原学习位置；
4. 在题目A、题目B、资料视图之间切换时，回答和草稿仍归属于原目标；
5. 在来源失效、版本变化、超限、超时或未知执行时得到真实状态和可执行恢复入口。

## 2. 范围

### 本卡必须完成

- 统一助手单入口，保留当前显式取材和上下文冻结。
- 短答与完整解释两种意图；完整解释不强制逐步点击继续。
- 解释目标冻结：`request_id`、`topic_id`、目标类型和内容版本不可随当前视图改变。
- 资料页级锚点与题目任务级锚点；服务端生成并校验来源身份、版本和有效性。
- 解释正文单一权威存储，兼容旧 `reply`／`claims` 只读读取。
- 查看／展开／来源核查／定位／重读不产生模型生成；新问题、追问、续写、显式重试使用新请求。
- 整条输出校验后发布；截断、来源失效、版本变化和未知执行不得发布为完整答案。
- 题目／资料切换、助手关闭、刷新和返回的确定性状态回放。
- 隔离Mock、单元／API／浏览器测试和可读实施报告。

### 本卡明确不完成

- 手机网页、原生App、全站视觉重构。
- 图片、纸笔照片、扫描件、图表视觉理解和OCR。
- 跨资料自主检索、联网来源、网页嵌入。
- 永久贴条、资料链接持久化、题目↔知识双向链接。
- 多Agent并行、递归委派、长期记忆、自动学习规划。
- 修改原件、自动提交、改分、宣称掌握或绕过重测帮助同意。

## 3. 非阻塞并行项

以下内容继续验证，但不阻塞本卡核心实现；若发现直接破坏本卡行为，再升级为阻塞：

- 原生浏览器125%缩放；
- 完整Tab顺序、Escape、焦点返回和中文组合输入；
- PDF内部像素级渲染保真；
- 真实迟到模型事件的端到端回放。

样板／浏览器证据必须继续标记“未验证”，不能写成通过。

## 4. 建议数据契约

```ts
type DocumentAnchor = {
  kind: 'document'
  course_id: string
  source_id: string
  source_sha256: string
  preview_version: string
  page: number
  precision: 'page'
  valid: boolean // 服务端生成
}

type TaskAnchor = {
  kind: 'task'
  course_id: string
  session_id: string
  task_id: string
  content_version: string
  precision: 'task'
  valid: boolean // 服务端生成
}

type ExplanationParagraph = {
  id: string
  purpose: 'evidence'|'explanation'|'step'|'caveat'
  source: 'verified_evidence'|'model_reasoning'|'user_text'
  text: string
  citation_ids: string[]
}

type Explanation = {
  schema_version: 1
  request_id: string
  topic_id: string
  origin: DocumentAnchor|TaskAnchor
  target_anchor?: DocumentAnchor|TaskAnchor
  paragraphs: ExplanationParagraph[]
  citations: Array<{id: string; anchor: DocumentAnchor|TaskAnchor; title: string; quote: string}>
  status: 'complete'|'failed'|'cancelled'
  content_version: string
  generated_at: string
}
```

契约要求：

- `valid`、`precision`、`anchor`身份由服务端确定；客户端和模型不得自报有效。
- `source='verified_evidence'` 的段落必须有服务端校验的引用；模型推理和用户文字不得伪装成资料证据。
- 本卡只支持页级资料锚点和题目级任务锚点，不提供文字框、区域框或题目步骤精确定位。
- 旧消息只读适配，不回写旧正文或破坏幂等指纹。

## 5. 请求与交互规则

| 操作 | 是否生成模型请求 | 规则 |
|---|---:|---|
| 查看已发布回答 | 否 | 从服务端读取，不改请求状态 |
| 展开完整回答 | 否 | 只改变显示状态 |
| 核查引用／定位资料 | 否 | 重新校验来源后执行确定性定位 |
| 重读请求状态 | 否 | 不自动重发未知请求 |
| 新问题 | 是 | 新 `request_id`，冻结当前目标与附件 |
| 追问／续写 | 是 | 新 `request_id`，记录 `continuation_of` |
| 未发布失败的显式重试 | 是 | 新 `request_id`，记录 `retry_of`；已发布请求不能作为retry |

题目B不得显示题目A的解释。切资料、关助手、切题和刷新不改变已冻结请求的归属；迟到结果只能写回原主题。来源失效时保留历史文本和用量，禁用当前定位，不跳转同名新资料。

## 6. 长解释策略

- 默认短问题采用短答；用户明确提出“完整解释／完整推导／详细说明”才进入长解释意图。
- 长解释在用户主动选择后进入可阅读区域；助手仍保留继续提问入口，不复制两份权威正文。
- 单次先采用整条生成、整条引用校验、整条发布；输出超限或校验失败时保留诊断和原始结果，不发布不完整正文。
- 本卡不提供token滑杆，不强制用户管理模型预算。512与3000～6000只是待测候选上限，最终按真实输入和完整性测试定稿。
- M2未验证的125%、IME和PDF像素问题不通过增加第二套聊天或临时硬编码解决。

## 7. 开发任务分解

### M3-A 服务端契约

- 增加Explanation版本化DTO和服务端组装／校验。
- 接入DocumentAnchor／TaskAnchor白名单校验及来源版本检查。
- 保持旧消息读取、请求幂等、失败／取消／未知状态和用量记录。
- 增加合法／非法Anchor、跨题、跨课程、失效来源和重复请求测试。

### M3-B 生成与上下文

- 根据短答／完整解释意图选择输出预算，但不让前端暴露token设置。
- 保留上下文trace、历史范围提示和用户纠正关系。
- 确保模型解释、核验资料、用户文字分段，引用只来自本请求Evidence。
- 对超限、截断、版本变化和未知执行给出可读状态。

### M3-C 前端呈现

- 助手消息支持短答、完整解释、来源核查、定位和返回。
- 已生成内容展开零调用；继续追问明确创建新请求。
- 展示资料／题目身份、页级／任务级精度和失效状态；不显示内部e1等工程ID作为主文案。
- 保持题目草稿、资料阅读位置、助手关闭状态和历史只读。

### M3-D 测试与报告

- 更新确定性Mock响应，覆盖短答、长答、来源、题目隔离、失败和恢复。
- 运行前端定向测试、构建、隔离API／浏览器回放。
- 保存每次测试的viewport、浏览器、代码版本、证据路径和未覆盖项。
- 不运行真实模型，不发送个人资料，不迁移正式库。

## 8. 验收标准

### 必须通过

1. 短答默认留在助手；用户主动选择后才打开完整解释区域。
2. 完整解释正文只存一份，展开不新增模型调用。
3. 完整解释中的资料事实、模型解释和用户文字边界可见且可校验。
4. DocumentAnchor／TaskAnchor身份、版本、有效性和精度不能由客户端或模型伪造。
5. 题目A／B、资料A／B、旧请求／新请求互不污染；迟到结果不写入新目标。
6. 失效来源不能定位，历史和用量仍可读／导出。
7. 重试、续写、追问使用新请求并正确关联；未知结果不自动重发。
8. `npm test`、`npm run build`和新增隔离浏览器回放通过。

### 本卡不作为通过条件

- 原生125%浏览器缩放；
- 完整中文IME与Tab矩阵；
- PDF像素级渲染保真；
- 真实模型语义质量、个人资料验收、学习效果。

以上项目保留并行质量记录，进入真实资料／模型验收前必须补齐或明确范围。

## 9. 交付物与禁止事项

交付：实现差异、DTO／迁移与回退说明、隔离测试、浏览器证据、未覆盖清单、当前能力说明。禁止删除旧失败、清空用户数据、修改正式库、擅自增加真实调用预算或把Mock预写内容标成真实回答。

M3-alpha通过后，才讨论M4真实资料与真实模型验证；M3-alpha通过不等于完整Agent或最终产品完成。
