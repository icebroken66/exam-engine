# FE-V09：统一助手交互收敛与界面重设计任务书

日期：2026-11-23｜版本：1.0｜状态：用户已确认启动，第一阶段可点击样板待设计评审，未批量推广。

依据：[讨论记录](../原始讨论与设计/2026-11-22_资料学习工作区讨论记录.md)、[状态契约](../原始讨论与设计/学习Agent_状态与上下文契约草案.md)、[FE-V08](FE-V08_无模型任务主题与上下文底座任务书.md)及其[报告](../实施验收与复核/FE-V08_实施与验收报告.md)。本卡吸收用户截图批评和已做的紧急UI简化，不能将隐藏几个按钮当成整个设计已完成。

原编写轮次不自动开工；用户后续明确“确认”启动FE-V09。依第3节先交付可点击样板供评审，未授权模型或新后端生成能力。编号及阶段状态统一在[开发计划](开发拆分与PR计划.md)。

## 1. 问题与目标

现有助手将技术阶段暴露给用户：旧带学与问题记录双入口、版本启用、存储模式切换，以及大量导出、重载、预检和事项管理控件。用户实际要做的是提出问题、附带内容、查看回答并继续学习。

本卡目标：把现有底座收敛为一套轻量助手体验。用户不必先建事项、选模式、手动保存，再执行检查。后台保留任务、主题、版本、兼容与恢复；界面只在需要时解释它们。

设计原则：**一个助手入口、一个当前输入区、一个主要动作；有需要才显示附件确认、历史或恢复操作。** 不以复杂Agent架构为复杂UI辩护。

## 2. 范围与能力边界

| 必须完成 | 本卡不做 |
|---|---|
| 统一助手布局、输入、附件、历史与状态设计 | 新真实生成服务、网络搜索、图片识别、专家Agent执行 |
| 自动草稿保存、首次使用不需技术设置、恢复保护 | 全量自动迁移本机旧记录、云同步、自动合并冲突 |
| 助手内取材及简化的明确确认 | 自动读取用户勾选／草稿／全部笔记 |
| 后台主题／事项与前台自然语言表达分离 | 全站导航或阅读器再次重构、手机网页 |
| 旧记录只读访问、工程调试与普通界面分开 | 删除旧服务数据、修改评分／独立性规则 |

当前能力：v2只准备上下文，没有真实回答；旧带学后台仍存在，但普通入口已停用。本卡不恢复双模式，也不把无模型底座伪装成真实聊天。真实教学服务合流应另有任务，通过同一个输入入口接入，不能再次让用户选择旧版／新版。

如本卡开始时真实发送已由另卡完成，只按已验收接口适配，不借本卡偷偷实现或调用模型；未完成就沿下述未接通状态验收。

## 3. 设计交付先于批量改动

1. 核实最新代码、临时简化和未提交改动；记录基线及本卡差异，保留旧记录，不回滚用户其他工作。
2. 用同一公开课程与文档制作一套可点击精细样板，至少有：首次使用、附带内容、历史恢复、保存冲突四个场景，先在1440×900评审，再检查1024×768。
3. 展示默认界面截图及主操作路径，说明每个常驻元素为何必要。用户能按实际任务评审，不要求评价组件库或技术名词。
4. 评审后沿同一版本改进，不长期并排保留A/B或旧／新助手。未收到用户反馈不写“设计已认可”；可继续独立底座／测试工作，不批量推广未经认可视觉。

## 4. 正常界面与输入契约

### U1：默认布局

- 顶部只显示“AI学习助手”、当前对话简短标题／历史入口、一个新对话动作和关闭。标题不重复多层显示，不出现“服务端会话”“上下文准备”等工程名称。历史和标题可合并为一个入口。
- 中部为对话／问题历史或轻量空状态。不能用事项控制台、存储说明和管理按钮占满内容区。
- 底部是输入框、添加内容入口、主要动作及一行必要状态。默认不常驻多个折叠面板列表；低频菜单用一个“更多”入口承接，不只是把十几个按钮原样藏进十几个details。
- 初次打开可以立即输入；不要求先创建主题或命名。无服务端记录时采用本机未发送草稿，首次实际编辑后再按已定义规则惰性创建主题；纯打开和导航不创建事项／调用模型。
- “新对话”先创建空白本机编辑状态，旧草稿自动保存／保留；无文字无附件的空对话不制造多条服务端垃圾记录。对话标题用首段文字的确定性摘要，可编辑，不为起标题调用模型。
- 对话中的内部single／independent／compare保留数据语义，普通用户不必选枚举。明确比较多个目标时才解释该行为，不默认展示范围表单。

### U2：草稿自动保存与唯一主动作

- 编辑停止后约600ms启动保存，最多一个写请求在途，回执后补存后续改动。保持CAS／command_id，不能因自动保存绕过冲突或覆盖新文本。参数可微调但需记录，不能每个键发请求。
- 保存中、已保存、未保存反馈简短且准确；成功回执前不显示成功。无需普通用户手动点“保存主题草稿”，正常态不显示导出／重读／Manifest检查。
- 真发送未接通时明确一行“回答功能尚未接通，内容可先保存”；主动作显示禁用的“发送”，附可访问的禁用原因。自动保存可用，不能把“保存”“检查”伪装成已发送问题或AI回答。
- 如已有真实发送能力，主动作才启用发送，并沿独立真实契约执行。输入中文Enter不误发；发送快捷键在实现时固定并提示，未接通时任何快捷键均不发请求。
- 本卡不凭空新增聊天消息表或假气泡。若只有未发送草稿，内容区如实展示状态；真实历史、未发送旧记录和示例数据须区分。

## 5. 添加内容与上下文

- 输入区仅一个“添加内容”入口。点击后提供与当前视图有关的选项：从课件选字／框选、附带本题、附带当前作答、附带已提交作答／反馈。不可用项省略或清楚解释，不能一排全铺。图片上传未实现则不提供假可用入口。
- 课件临时取材在中央有清楚状态，选择后在助手显示短预览与“添加／取消”。默认新增，只有有明确替换需求时才展示替换选择；不能让用户每次都选择技术绑定方式。
- 普通个人高亮、框选、勾选答案不改对话附件。Esc／取消恢复原阅读模式，不制造笔记；对话草稿保留。
- 已附内容以紧凑附件条／卡片呈现：名称、页或题目、未提交等必要身份、移除和展开。默认不铺全文、hash、版本、坐标和trace。完整选文可按需核对；区域图像未提供时只称“区域位置”，不假装看懂图片。
- 本题附件可在用户明确添加时，由后台建立／复用事项与相应主题；不要要求先“建立事项与主题”。已有草稿目标不同时，用一句话说明并提供保留原对话／新对话选择，不静默搬走内容。
- 绑定前如有正文待存，系统先完成保存再绑定；不可要求用户先手动保存才允许确认。失败停止后续，保留原文和候选附件，显示重试。
- 换页／换题后附件不自动更新；只在存在明显对象差异时提供简短“仍关联第X题”，可移除或明确换用当前内容，不反复弹窗。
- 限额沿FE-V08，不静默截断；达到限额时在添加环节说明，不持续占用输入区。

## 6. 历史、事项和旧功能

- 历史对话通过顶部一个入口访问，显示用户可识别标题／更新时间；选择后恢复对应草稿与附件。当前对话不重复显示选择器＋摘要卡＋标题三遍。
- 未完成学习事项提供“继续之前的学习”等自然入口，优先显示有关项；暂停／恢复等管理动作放对应条目中，不让用户每条消息维护事项状态。
- 旧记录只读保留在历史／更多入口，原始数据可导出；旧本机内容不自动上传，复制到新草稿需明确选择，非空草稿先保护。不能为了简化删除数据，不能把历史未发送记录显示成AI回复。
- 旧带学组件／服务可保留做兼容与后端验证，但普通入口、正常页面DOM和说明中不出现“切到旧带学”。调试入口仅开发／测试显式启用，不出现在用户导航。
- 旧题求助尚不能在新入口执行时，准确显示能力边界；不以隐藏服务就宣称替代完成。未来真实合流须沿新助手完成同意／帮助规则，不恢复第二聊天UI。

## 7. 错误、恢复与技术信息

- 正常状态无需用户选择本机／服务端模式、schema版本或启用功能开关。默认行为由产品确定并提供简短保存范围说明；不静默上传既有本机资料。
- 保存失败提示“尚未保存，内容仍在”，提供重试；冲突提示另一窗口已更新，保留当前草稿，提供查看／导出当前内容和显式重载。仅显示与当下错误有关的操作，不要求先理解CAS。
- 不能将错误恢复全部藏进菜单。失败中的候选选区和输入不丢，重新载入若会丢未保存内容需明确一次确认。
- JSON原始导出、Manifest、request／revision等收进开发诊断；历史备份导出留在用户更多菜单。若生产问题确需原始导出，可从错误详情进入，不默认展示两三个相似导出按钮。
- 面板关闭不取消保存或清空草稿；切课程保留未存内存，硬关闭未确认保存内容不保证恢复，按已有保护说明，不以自动保存承诺零丢失。

## 8. 设计与工程规范

- 复用实际BoardUI免费组件，先读Skill／已安装源码；优先已有Button、Input／Textarea、Popover／Menu等，不为本卡依赖Pro聊天模板。缺组件时按需检查来源、许可和依赖，不全项目init。
- 统一既有语义token和复合排版，沿cx及本项目路径约定。App、独立阅读工作台使用同一助手展示层，视图变化不复制另一套输入状态。
- 错误、保存状态与禁用能力说明均为真实状态，不造进度／思考动画。内容区、输入区、顶部各承担单一职责。
- 保留足够正文空间，1024px展开助手仍可输入和阅读；长标题、长选文和公式在自身区域折行／滚动，不挤出关闭、输入或主操作。焦点、标签和减少动画支持完整。
- 自动保存与惰性建主题需有有界重试、过期回执和command重放保护。未明确可重试的结果先读取，不无限重发建主题，不自动调用任何模型。
- 后端尽量复用FE-V08接口。确需小接口适配先列差异与兼容；不得把完整真实生成服务藏入UI任务。原评分、任务、帮助与来源生命周期保持。

## 9. 验收规范

真实Edge／Chrome，1024×768、1440×900、1920×1080，关键场景原生100%／125%缩放。截图须来自实际可操作页面、同一公开样本；不要只给静态效果图。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| U01 | 正常首次打开与有历史打开 | 只有一个助手，无旧／新、记录／带学双入口，无存储／版本启用步骤 |
| U02 | 零主题直接输入、新对话、空对话关闭 | 可立即写，后台有界惰性创建；纯打开／空白不造事项和重复主题 |
| U03 | 自动保存、在回执期间继续输入 | 无需手存，准确状态，旧回执不覆盖新字，最终正文完整 |
| U04 | 无模型状态、Enter／快捷键、主操作 | 明确未接通，发送不可用且原因可达，无假回复、无网关／帮助调用 |
| U05 | 添加课件／本题／草稿／已提交反馈 | 一个入口、选项相关，必要公开范围与未提交身份正确，不强迫建事项 |
| U06 | 确认／取消取材，待存正文后附带 | 不丢文、不创建个人笔记，无需手动先保存；失败保留候选 |
| U07 | 翻页／换题、目标冲突、附件移除／替换 | 不自动跟随，目标可知，不静默移动旧草稿到新主题 |
| U08 | 历史切换、旧记录查看／复制、两课程往返 | 草稿与附件隔离，旧内容身份清楚，不自动上传／覆盖 |
| U09 | 自动保存断网／409／超时及命令丢回执 | 正确停写／重读／重试，恢复动作当场可见，未存内容保留可导出 |
| U10 | 关闭重开、刷新、后端重启、全新浏览器 | 已保存内容真实恢复；未存限制明确，不用缓存冒充服务端 |
| U11 | 只读归档、失效来源、坏格式／限额 | 原规则保持，错误可理解，不造可用按钮或偷偷截断 |
| U12 | 正常DOM与键盘焦点 | 无隐藏第二聊天挂载抢焦点／发请求；Tab、Esc、中文输入可用 |
| U13 | 三尺寸与125%、长标题／选文／历史 | 无横向溢出、输入被挤走或关闭不可达；不常驻工程字段 |
| U14 | 正常与冲突视觉对照 | 正常只显当前任务所需操作；管理为单入口、冲突恢复直接可见 |
| U15 | 旧服务兼容、笔记／擦除、正式提交与重测 | 数据不丢、现有业务保护不退化；诊断测试不当普通用户路径通过证据 |
| U16 | 用户独立走“输入→附带→换页→恢复” | 不需解释主题／事项／预检／存储含义；记录真实卡点与反馈，不造满意度 |

正常态检查：主区不展示命令ID、revision、schema、Manifest、迁移模式；主操作区不能并列多个保存／发送／检查按钮。用户需要的附件摘要与错误不能为了控件数量指标而隐藏。

## 10. 交付、收口与回退

1. 可操作样板和最终页面，正常／附件／历史／错误四状态、同视口前后截图及用户评审记录。
2. 控件去留表：保留、合并、移到更多、仅诊断、停止普通入口；说明旧记录如何访问及未实现能力，不以“后台还有”冒充用户已能使用。
3. 自动保存／惰性主题创建时序和故障说明，接口差异／旧数据兼容、正确回退及复现命令。
4. U01～U16逐项结果，实际环境、样本hash、精确HEAD／工作区状态、源码指纹、失败与修复证据，私有记录不入库。
5. 运行受影响助手／导航／reader浏览器、单元、构建、维护回归及diff检查；自动保存、并发和旧数据用临时真实API验证，不只依赖前端Mock。不得放宽原CAS／上下文隔离断言迁就新UI。
6. 更新design.md中助手规则及讨论／开发计划。前轮临时简化回归只作基线，不冒充本卡通过。

U01～U15及工程验证通过，U16设计评审完成后标已完成；无用户反馈记待验收。数据丢失、暗中发送／迁移、假回答、跨题污染、第二套入口回潮、需要手动工程步骤才可正常输入为阻塞。

回退展示层时保留旧／新数据和已存主题，不清理存储；关闭新自动写入并保留只读／导出。完成后停止本卡，再单独规划真实请求生命周期与教学适配，不自动开启模型。
