# FE-V10 复核与待收口问题

日期：2026-11-24。用户要求复核当前实现是否完成目标；本次续跑验证针对性真实回归与测试环境修复。

## 结论

FE-V10 的**工程最小闭环基本完成**：统一助手可以发送，服务端保存请求与消息，支持上下文冻结、幂等重放、停止、未知执行恢复、PDF页级引用、题目附件、题目隔离及引用返回。现有报告记录后端266项、前端53项、既有浏览器23项与生成专项27项通过；本轮重新运行 `npm test` 为53项通过，设置 `PYTHONUTF8=1` 后后端pytest通过。未设置该变量时，后端保护测试因Windows子进程中文输出编码产生环境性失败，见“测试环境问题”。

但不能把 FE-V10 标记为整卡完成，也不能说已经证明满足用户最终的学习目标。真实模型累计22次调用／32218 token，开发场景全部有生命周期结果；其中D03、D05、D11的部分论断被初审认为超出引用支持，证据支持暂评1分。初审文件明确 `human_reviewed=false`、`development_passed=false`；6项保留场景各运行2次、人工逐条核对和本人约20分钟试用均未完成。

## 已符合目标的部分

- 用户可以明确添加资料片段、题目、作答或反馈后提问；普通阅读停留、笔刷和未确认选区不会自动成为上下文。
- 请求目标绑定Topic与题目身份，切换资料、关闭助手和换主题不会把回答写入新主题；重复发送和丢回执不会静默重复调用。
- PDF片段在服务端核验原件hash、页码和预览版本；无法匹配时只能降级为“用户提供文字”，不会伪称课件原文。
- 引用动作由服务端生成并在点击时重新校验，能返回资料页或题目记录；无效证据、虚构页码、网址和本机路径不会正常发布。
- 题目帮助继续遵守原有重测同意、running保护、教师字段隔离和正式作答边界。

## 尚未达到的目标

### 1. 证据支持质量未通过

当前系统能保证“引用ID存在、引文属于该Evidence”，但还不能保证模型的每个解释都被引文充分支持。D03、D05、D11已经出现部分论断超出短引文支持的情况。这正是用户要求的“来源可靠、避免错误”的核心门槛，不能用引用按钮存在或自动化通过代替。

处理要求：人工逐条核对原件、论断和引用关系；必要时调整Evidence片段组装、提示约束或回答策略；修复后重跑原开发场景并保留失败样本，不能直接进入保留集。

### 2. 缺少人工质量验收

AI辅助初审只能定位风险，不能填写人工通过。必须由人工逐条核对事实、关键符号、回应卡点、上下文范围、纠正能力和不确定性处理，并记录理由。当前 `development-ai-review.json`（位于本地真实运行证据目录）尚未形成用户可接受的人工结论。

### 3. 缺少保留集与本人试用

6项保留场景尚未运行；本人需要自然完成“读资料提问→围绕题目追问→去资料查阅→回原讨论→点击引用”的约20分钟试用。没有这两层证据，无法判断输出是否稳定、入口是否增加负担、引用是否真的有帮助。

### 4. 用户完整产品目标仍未全部实现

本卡明确后置的纸笔／图片理解、扫描件和图表识别、跨资料自主检索、网络来源、AI在资料上生成贴条、知识双向链接、多专家协作仍未实现。当前完成的是“文字／可提取PDF＋已有题目”的最小闭环，不能等同于完整多模态学习Agent。

## 测试环境问题

直接运行 `.venv\\Scripts\\python.exe -m pytest backend` 时，`test_unapproved_live_runner_has_no_network_or_database_side_effect` 读取子进程stdout失败，原因是Windows当前代码页无法解码中文输出，导致 `stdout` 为 `None`。设置 `PYTHONUTF8=1` 后后端测试通过。该问题不表示生成链路业务失败，但应修复测试脚本／子进程编码，使默认命令在本机直接通过，避免验收依赖隐藏环境变量。

续跑时该问题已修复：[test_assistant_generation.py](../../../../backend/tests/test_assistant_generation.py) 的子进程显式继承 `PYTHONUTF8=1`，并对非JSON诊断输出使用替换解码。专项测试默认运行通过；后端全量测试和前端 `npm test` 也通过。仍有一条 `httpx` 与 Starlette 的弃用提示，不影响测试结果。
