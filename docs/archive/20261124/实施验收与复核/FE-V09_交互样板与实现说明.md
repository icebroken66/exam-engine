## 四种场景共用一套展示层

1. 首次：顶部“AI 学习助手”、历史标题入口、新对话、关闭；中部轻量留白与无回答说明；底部直接输入、“添加内容”、禁用发送、一行真实保存状态。不要求建主题、命名或保存。
2. 附件：添加菜单按当前资料/题目能力提供选字、区域、本题/草稿/已提交记录；短预览后添加/取消。常驻仅紧凑附件卡，全文按需展开，版本/hash/trace退出正常界面。
3. 历史：顶部标题打开列表，以标题/更新时间/未发送身份辨认，选中恢复草稿与附件；旧记录另一个列表入口，只读/导出或明确复制文字，不自动上传本机内容。
4. 冲突：输入保留，提示另一窗口更新，当前错误旁可重试/导出/显式重载；正常没有导出/重载操作排布。重载丢未存内容需一次确认。

## 自动保存时序与接口

首次打开仅GET，不创建主题或事项。新对话仅创建内存空白编辑状态；第一次非空编辑静置600ms后POST /topics（标题首段确定性摘要≤32字符），然后PUT /composer。最多一个写请求在途，回执之后比较正文版本补存，旧回执不覆盖新输入。附件确认先flush正文，再以最新revision POST binding。空白无附件不建立服务端记录。切换/关闭不销毁保存控制器；跨课隔离内存。失败停止自动重试，显式重试复用原command_id。冲突停止覆盖并提供读取/导出，不自动合并。不会为了起标题调用模型。

复用FE-V08现有API与DTO，无新表/迁移/生成接口；既有主题标题编辑若需服务端支持另列最小适配，首轮样板不更改后端契约。取材复用原事件桥与ReaderLab唯一状态。正式学习/帮助/评分不改。本机旧记录仅用户点击读取时访问本机旧key，不扫全部存储。
