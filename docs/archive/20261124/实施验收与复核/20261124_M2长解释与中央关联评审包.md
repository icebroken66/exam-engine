## 启动

1. 在仓库根目录运行 `npm run build`。
2. 运行 `npm run dev:web -- --host 127.0.0.1 --port 7176`，打开 `http://127.0.0.1:7176/workspace-review.html`。
3. 使用桌面浏览器依次点 P1～P4。样板中的“公开夹具／预写内容”是刻意标识，不能当成真实回答质量证明。

## 四条路径

|路径|操作|可观察结果|失败／恢复|
|---|---|---|---|
|P1 局部概念|在资料区点击解释“公比”|短答、资料名／页级来源，关闭回原位置；无笔记改变|切换资料后仍能关闭；未实现区域精确高亮不伪造|
|P2 完整推导|点击完整讲解|一次展示长中文、公式、表格、边界与验证；内部滚动，不要求逐步继续|窗口变窄仍可滚动；关闭回资料；内容为预写夹具|
|P3 依据往返|定位第二资料第2页，再返回起点|起点／证据目标分开，资料名／页／页级精度可见|来源切换不改题目；没有区域坐标时显示页级回退|
|P4 做题中断|编辑题目草稿→解释当前步骤→关闭|草稿、题目身份、讲解主题分离；关闭后仍在原题|换路径不覆盖草稿；纸笔图片显示为未接入能力|

每条路径都包含正常、失效／限制和恢复信息。P4 只展示文字草稿，未声称能读纸笔照片或图表。

## 推荐方案与替代方案

推荐：中央内容保持主要阅读空间，长解释作为可关闭的临时并排阅读区；助手只负责意图、请求状态和入口。来源点击后由服务端校验，再定位资料或题目；无区域证据时回退页级。临时解释不写 ReaderSnapshot、不自动生成批注。

替代：长解释在助手面板内展开，并提供“在中央查看”按钮。优点是实现更小，缺点是长公式和比较资料时阅读空间不足，往返关系更难保持。两者不同时长期保留；本包只实现推荐方案样板，待评审选择。

## 待评审决定

## 契约草案（候选，非现有 API）

```ts
type DocumentAnchor = { kind: 'document'; course_id: string; source_id: string; source_sha256: string; preview_version: string; page: number; precision: 'page'; valid: boolean };
type TaskAnchor = { kind: 'task'; course_id: string; session_id: string; task_id: string; content_version: string; precision: 'task'; valid: boolean };
type Explanation = {
  schema_version: 1; request_id: string; topic_id: string; target: { kind: 'concept'|'question_step'; id: string };
  status: 'complete'|'incomplete'|'cancelled'|'failed';
  paragraphs: Array<{ id: string; purpose: 'evidence'|'explanation'|'step'|'caveat'; text: string; source: 'verified_evidence'|'model_reasoning'|'user_text'; citation_ids: string[] }>;
  citations: Array<{ id: string; anchor: DocumentAnchor|TaskAnchor; title: string; quote: string }>;
  origin: DocumentAnchor|TaskAnchor;
  target_anchor?: DocumentAnchor|TaskAnchor;
  content_version: string; generated_at: string;
}
```

本轮只承诺 `page` 与 `task` 两种精度；文字、区域和步骤精度留待后续契约，不在样板中伪造。合法：`status=complete` 且每个 `source='verified_evidence'` 段有一个服务器校验过的 citation；题目锚点不能填写 `source_id`。服务器生成并校验 `valid` 与 precision，客户端和模型不得自报有效。

合法 JSON：`{"anchor":{"kind":"document","course_id":"c1","source_id":"s1","source_sha256":"sha","preview_version":"pdfjs-v1","page":2,"precision":"page","valid":true}}`；题目合法 JSON：`{"anchor":{"kind":"task","course_id":"c1","session_id":"s1","task_id":"t1","content_version":"v1","precision":"task","valid":true}}`。

非法 JSON：`{"anchor":{"kind":"document","course_id":"c1","source_id":"s1","page":99,"precision":"region","valid":true}}`（缺 hash／版本且使用本轮未承诺精度）；`{"anchor":{"kind":"task","course_id":"c1","source_id":"s1","task_id":"t1","valid":true}}`（题目锚点混入 PDF 字段）。非法还包括客户端自行提交 assistant 段、citation 指向失效版本、用户文字 claim 冒充 evidence、临时解释写入 ReaderSnapshot、展开已生成内容再次产生 request。

正文单一权威存储为 `paragraphs[].text` 的服务端组装结果；旧 `reply`／`claims` 读取适配只读，不回写旧消息。`schema_version` 升级需保留旧导出和幂等指纹。M3 前不迁移正式库；隔离库先演练。若回退，停用新解释的写入、展示或定位入口，但保留已经产生的解释、来源、请求和用量记录；历史读取与只读导出继续可用，禁止删除用户内容。恢复启用时沿原 request／版本继续读取，不重新生成。

## 生命周期、预算与恢复

- `accepted → preparing → running → validating → published`；失败、取消、超时、未知均保留请求和用量。没有段落级校验前继续整条校验后发布。
- 查看、展开、引用核查、定位和重读状态：零模型生成调用；普通新问题、明确重新生成、对新内容追问和继续生成：都会产生新的生成请求。继续生成使用新 `request_id`、`continuation_of`（父回答／段落／冻结范围）和独立预算；失败重试才使用 `retry_of`，已发布结果不得作为 retry_of。未知结果先 GET 原请求，禁止自动重发。
- 推荐先测短答 512、完整讲解 3000～6000 输出 token 的候选上界，实际 M3 根据资料复杂度和完整性核对定稿；不提供 token 滑杆。记录延迟、输入／输出用量和截断原因。
- 超限、截断或校验不完整时保留诊断和原始结果，但状态为 `failed` 或 `blocked`，不发布 `incomplete` 正文。没有独立的段落校验、持久化、取消和曝光契约前，不做部分发布。换题、关助手、刷新不改变请求归属；来源版本变化阻止发布并提示重新取材。
- 长历史只带入同主题、同范围且有 trace 的有效记录；用户纠正保存原话关系，不用摘要替代。首版可显示范围限制，不承诺无限记忆。

## 影响与未实现

本包只新增样板、评审文档和确定性状态测试，不接真实模型、不做正式迁移、不发送个人资料。M3 还未实现中心临时解释、持久化 LearningArtifact、图片／纸稿理解、跨资料自主检索、网络来源、永久贴条／双向链接、多专家。
