## 原生缩放与定位方法

Chromium原生每站点缩放preferences使用 partition.per_host_zoom_levels.x；zoom_level=log(1.25)/log(1.2)。只在新建临时测试profile写入，不触碰用户浏览器profile。读取实际devicePixelRatio比率、innerWidth／innerHeight、CSS zoom=1和visualViewport.scale=1交叉验证；不使用deviceScaleFactor、CSS zoom或Emulation.setPageScaleFactor冒充。

有界面Windows窗口受屏幕工作区限制，无法真实形成1920×1080 CSS区域；对应探索记录不能当三尺寸矩阵。最终矩阵使用Edge／Chrome的headless原生浏览器布局缩放，viewport:null，CDP只调浏览器窗口尺寸而不调页面缩放，实际CSS视口为1024×768、1440×900、1920×1080。另有界面探针在系统DPR1.25下得到原生125%的DPR1.5625，验证同一缩放机制；全屏和真实失焦另用有界面浏览器。

每组以三个独立canvas相对位置建立笔迹、高亮和贴条；笔迹端点经SVG screen CTM变换，高亮DOM四角、贴条DOM左上锚点与canvas坐标比较。50/100/200%／适应宽度往返10轮，工作台另加适应整页；检查助手、滚动、翻页返回、刷新重选。所有误差阈值仍为4 CSS px；最终1176次测量最大误差0.015 CSS px，见results.json。原坐标不改写为屏幕坐标。

探索失败保留：native-zoom01～03为Windows窗口取整／尺寸限制；04为展开贴条挡住下一笔；06／07为模式切换出现笔宽参数后过早取布局坐标。脚本改为收起已建贴条、切换模式后两帧等布局稳定、重读页面边界，没有改产品坐标或放宽4px阈值。extra01错误地再次点击已恢复打开的面板，以及有选区时一次Esc就期待关闭面板；改按实际的先取消选区、再关闭面板顺序，保留原失败，extra02及extra-final通过。
