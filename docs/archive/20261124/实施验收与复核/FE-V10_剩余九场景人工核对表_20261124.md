## D06：切换资料后回到原主题

状态：published，真实模型输出

用户：解释生产者与消费者的同步，随后我会去阅读资料再回来。

AI回答：
资料指出：“Mutual exclusion protects shared data.”

生产者—消费者问题通常用有界缓冲区说明：生产者把项目放入缓冲区，消费者从中取出。同步要保证两件事：访问缓冲区时互斥，避免同时修改共享状态；以及缓冲区未满时才生产、非空时才消费，避免溢出或取不到项目。

一种常见做法是用三个信号量：`mutex = 1` 保护缓冲区；`empty = 缓冲区容量` 记录空位数；`full = 0` 记录已有项目数。生产者依次执行 `wait(empty)`、`wait(mutex)`、放入项目、`signal(mutex)`、`signal(full)`；消费者依次执行 `wait(full)`、`wait(mutex)`、取出项目、`signal(mutex)`、`signal(empty)`。其中 `wait` 在条件不满足时等待，`signal` 用来更新计数并唤醒等待者。关键是先等待空位或项目，再取得互斥锁；这样等待条件时不会占着锁，导致另一方无法推进。

用户：回来看刚才的同步解释。

AI回答：
资料原文是：“Mutual exclusion protects shared data.”

刚才讲的是生产者—消费者同步：`mutex` 保护缓冲区，避免同时修改共享状态；`empty` 记录空位数，`full` 记录已有项目数。生产者先等待空位，再取得互斥锁放入项目；消费者先等待有项目，再取得互斥锁取出项目。这样既避免缓冲区溢出或空取，也避免等待条件时占着锁、妨碍另一方继续。
