# 教学闭环与产品迭代方案

日期：2026-11-10。状态：待实施的设计与研究任务，不是新能力验收报告。本文说明维护阶段之后怎样推进产品；PR 状态与编号只维护在[本地 PR 计划](../阶段任务与契约/开发拆分与PR计划.md)。当前 PR-04 正在进行，本次不修改它的实现。

## 1. 目标与第一步

首个目标：围绕一个真实知识点，让系统能根据学生回应调整帮助，并自然回到一次未见题的独立作答。先证明一段教学流程能工作，再扩到单章节和时间规划。

最先做一个真实对话的人工推演：选现有已核查的选择 / 投影题，保留第二科目信号题作为后续验证。列出学生起步、部分正确、纠正导师、讲后仍不懂、要求完整讲解、暂停及准备独立检查的不同回应；逐条写出导师应观察什么、允许怎样行动、不能据此声称什么。由此暴露需要研究和开发的具体决策，不先设计大型学生模型。

维护 PR-04 / 05 完成并固定基线后实施行为变化；研究问题表、题包和人工推演可以先准备，不同时修改正在重构的业务文件。没有真人时可以完成研究、实现和工程 / 模型行为验收，但学习收益保持待验证。

## 2. 只研究会改变设计的三个问题

| 问题 | 需要查什么 | 本轮交付 | 停止研究、进入开发的条件 |
|---|---|---|---|
| 怎样判断卡点而不贴标签 | 形成性评价、错误诊断、可修正的学生理解记录；现有系统如何处理误判 | 三个以上真实表达的支持 / 反证表与最小记录契约 | 能区分学生原话、待确认推测与已核查表现，定义一次误判如何纠正 |
| 帮助什么时候变浅、换法或结束 | 教学支架、撤去帮助、掌握与迁移检查、无进展处理 | 行动决策表及其适用 / 不适用例子 | 对连续卡住、局部正确、主动求解和暂停都有可执行路径；不依赖固定轮数机械切换 |
| 怎样验证教会与产品价值 | 教学试验中的前测 / 未见后测、对照、顺序和观察者影响 | 题包、评审依据、试用流程及无效试验判定 | 能保留原答并说明什么结果支持 / 不支持本次设计，无需先证明普遍有效 |

每个问题先选 1–2 篇直接相关的原始研究，必要时读一个实现，达到决策所需即停止。数量是工作约束，不是研究充分性的证据。记录原文位置、研究对象、适用条件、局限、采用或不采用的设计及其检验方法；官方源码只能说明机制，不能单独证明教学效果。

既有开源研究和回放作为输入，不再重复搜集同类 Agent。研究过程中核对真实来源，不直接沿用聊天中未经复核的引用或数字。新增研究结论记入工作区 05 的专题摘要，并链接原论文 / 源码；本页不重复维护另一份文献库。

## 3. 最小教学闭环

流程是“观察 → 待确认解释 → 一次帮助 → 观察回应 → 调整 / 退出 → 独立检查”，不是强制每轮走完的状态机。

### 观察与待确认解释

复用现有带学消息、正式作答和帮助记录。新增记录只覆盖当前题 / 子技能：

- 观察来自哪个 message / attempt，学生实际说了什么或漏了什么。
- 可能卡点、支持依据、反证与仍不知道的部分。
- 采用过的帮助及学生回应；学生纠正后保留修订关联，旧判断不静默覆盖。
- 待确认 / 被支持 / 被反驳 / 已撤销等证据状态；这里表示某个卡点假设的状态，不是掌握状态。

例：学生说“我先筛东区再投影”，可以观察到未提数量条件，但只能推测可能遗漏，不能直接断言不会合取。追问或后续原答确认后才更新。没有正式提交时，不制造一次错误 attempt。

先评估现有 observation 与事件是否足够；确需新结构才新增字段或表，单独说明迁移、旧记录兼容与回退。不将教师侧参考答案或学生画像整体返回客户端，不建设跨课人格标签。

### 一次帮助与下一步选择

| 实际情况 | 可采取行动 | 验收时关注 |
|---|---|---|
| 无从开始 | 给一个能执行的小步骤，必要时解释最小先修 | 不以不断反问替代教学 |
| 部分正确 / 表达省略 | 保留正确部分，澄清遗漏条件 | 不把省略表述直接判成概念不会 |
| 学生纠正导师 | 修正当前假设并承认信息变化 | 不沿旧归因继续教学 |
| 同一种解释没有作用 | 换表示、反例或更小步骤，并观察回应 | 不只是改措辞重复结论 |
| 要求完整解法 | 可以完整讲，并如实标记帮助 | 不将同构示范说成轻提示 |
| 连续无进展 | 提供补先修、换路径、暂停的明确选择 | 不擅自宣告学生失败或掌握，不无限循环 |
| 准备独立尝试 | 说明即将换未见题，由学生显式进入 | 不将聊天小检查自动计为正式独立成功 |

模型提出动作及简短可核查理由，代码执行权限、来源、版本、帮助和推进规则。首版仍优先一轮一次教学调用，不先加第二个模型作为诊断裁判。

### 撤帮助与独立检查

小检查只用于观察刚才解释的局部，不新增掌握证据。独立检查另用未见题或实质变式，继续经过已有选题、验题、显式发布、正式作答和判分。

PR-06 实现前须明确：检查题属于哪个轮次、已有活跃题如何保留、返回入口、重复请求、生成失败、帮助和来源变化如何处理。不能另造一套不受会话边界约束的临时答题器。待答状态不得泄露该检查题的答案；求助后按现有规则转带学。

一次检查通过只支持这道题的表现；失败回到具体错误与可选下一步，不能自动证明前面的讲解无效，也不能强制无限练习。

## 4. 可执行的开发顺序

详细卡片在本地 PR 计划，本页解释产品依赖。

1. **完成 PR-04 / 05，结束维护阶段。** 达到既定职责与回归出口即可，不继续为整洁无限拆分。
2. **PR-08：研究决策、题包与闭环契约。** 做上述人工推演，整理三项研究决策、可核查题包、现有失败、最小接口 / 数据变化与验收。作为设计交付，不改教学行为；不因编号较大排到所有旧功能之后。
3. **PR-09：可修正的卡点观察与帮助调整。** 只改当前题教学；保留支持依据、修订与帮助选择，不同时扩整课覆盖。先工程和保留样本，再必要真实模型回放。
4. **PR-06：接回独立检查。** 复用原规划和正式评分，实现上节完整生命周期；同时服务到期 / 待补缺建议，避免两个重复的新题入口。
5. **U-01：真人检查闭环。** 可以提前收集现有基线的操作问题；新闭环就绪后按匹配题包验证独立应用，不等待整课和时间规划。
6. **PR-07：补真实新资料主链。** 与固定有效题的教学试验分开验收。若选定题包的解析或验题是阻塞，先前置一个有范围的最小修复，不绕过人工确认。
7. **PR-10：单章节复习试点。** 在单知识点闭环可运行后，定义一个真实章节的人工对照技能表、未处理 / 未诊断状态与续学规则。先验证漏覆盖和重复安排，不直接建设全课程知识图谱。
8. **PR-11：时间约束下的复习试点。** 在章节状态可解释后接入考试日期、可用时长、跳过和停止，安排可执行任务并随表现调整。题目用时只是估计，不承诺最优提分。

PR-10 / 11 目前只界定目标和进入条件，详细实现按前一阶段真实问题补齐。各阶段不以真人统计收益作为唯一工程推进门槛；未获得真人证据时可以继续有限工程工作，但不能扩成已证明的产品效果声明。

## 5. 如何判断这次工作是否值得保留

工程：修订可追溯，聊天不产生成绩，帮助 / 来源 / 并发边界正确，检查题发布与恢复完整。

模型行为：保存改动前失败与实际上下文；用未参与调试的新措辞测试纠正、局部成功、连续卡住和完整讲解。不把同一案例重复调通当成泛化。直接模型有合理指令、同模型和可比输出预算；相同证据与相同原始资料两类比较分开。按案例报告错误和退化，不编造总分。

真人：沿用[试用包](../../../../evals/tutoring/trial-protocol.md)，先确认未见题未暴露；保留前测、带学原话、帮助、后测、耗时与介入，条件允许隔天再测。重复题、观察者提示、题包不匹配或中途退出必须注明，不能算独立成功。1–2 人只能发现具体问题，不能推导普遍提升。

若在可比案例中系统仍明显妨碍模型，先定位资料裁剪、提示限制、卡点误判或操作负担；优先删除没有价值的限制，不用增加工具数量掩盖失败。若真人仍不能独立做题，复查前置基础、讲法与迁移题匹配，保留失败再调整。

## 6. 分工与当下交付

由开发代理负责查证研究、设计草案、实现、回归、回放和证据整理；用户负责课程范围与重要取舍的确认，并在可行时提供本人或参与者的实际学习反馈。答案可执行或推导核查时先独立核查，不把所有校验负担交给用户。邀请与外部沟通须另有明确授权。
