## 2026-11-22：前端与功能先后顺序的讨论

用户提问：新功能应先做前端还是先做功能？以下为代理本轮建议，尚待讨论，不是用户已批准的排期：

1. 先用具体任务和低成本交互草图明确体验：打开资料、选区提问、解释定位、返回原处、保存笔记；同时描述手机路径。
2. 精细实现前，对会影响设计的能力做最小技术验证：目标格式如何呈现、页／区域如何稳定定位、选区能否提取、笔记怎样关联原文。用实际课件验证，不先建设完整后端。
3. 根据结果确定最小数据和接口契约：资料／版本／页或区域锚点、笔记、对话上下文、AI 定位动作及失败回退。明确可展示的数据，AI 只能引用有效目标。
4. 做一个贯穿前后端的最小可用切片：一种资料格式、一个阅读界面、一个选区问答和回到原文的路径；再补持久化笔记、题目关联和其他格式。切片范围仍需收敛。
5. 基础能力可行、交互可用后，精修视觉并推广到其他页面；原型与正式展示组件尽量复用。

核心建议：体验设计先行，关键能力早验证，前后端按一条真实学习路径共同推进。避免整套高保真前端完成后才发现定位不可行，也避免后端全部做完才检查手机操作是否成立。

## 2026-11-23：做题交互、跨视图状态与 Agent 工具工作流（讨论草案）

用户明确区分上一轮资料查看场景，要求继续讨论做题、不同界面交换及 Agent 的工具和工作流。以下为本轮代理草案，尚未获得用户确认，不作为实现任务书或开工授权。

### 实现事实与本轮范围

现有题内带学已移入唯一助手侧栏，但底层仍有原带学和通用记录／预检两条路径；不代表服务端真实发送契约已经统一。现有显式关联本题可携带未提交选择／草稿。下一设计仍以助手内主动取上下文为目标，不能把原实现当作最终交互，也不应无意丢弃用户后来明确附带草稿的能力。

### 做题交互提案

- 同一个应用级助手承接资料、题目与答案讨论，不要求用户理解或手动切换两套聊天后端。助手可以显示当前所在视图的身份信息，但未明确附带前不读取答案草稿、个人笔记或任意页面内容。
- 助手内“添加上下文”提供本题、当前选择／未提交草稿、已提交作答与已公开反馈、选取片段等明确选项。附带草稿显示未提交，附带反馈不夹带尚未公开参考答案。
- 普通练习中先回应用户问题，可提供方向、局部步骤或完整解释，由实际求助意图决定，不机械强制苏格拉底反问。讲解期间中央正式答案不被覆盖，用户正式点击提交才评分。
- 独立重测中，与当前测评相关的解释、查资料等帮助需要在实际提供之前明确转带学；纯界面问题不一律算教学帮助。服务端统一检查当前测评及关联操作，不只相信客户端 kind 或模型 help_level。无法确定是否相关时让用户明确意图，不静默泄题或把所有日常阅读当作弊。
- 判分后围绕已提交原答解释；质疑评分可引导显式复核／人工纠正，助手不能直接改分。显示的对话不自动推进题目或宣称掌握。

### 跨界面交换提案

- 当前中央视图、助手会话、每条消息冻结的上下文是不同对象。打开资料不会替换题目关联，展开课程树不等于切课程，改变答案选项不会自动更新已附带的草稿。
- 单纯切换页面不清空对话／草稿，不暗中新建会话。助手显示当前关联对象以及与当前视图的差异，提供“改用当前内容／返回关联位置”。
- 从题目引用打开资料前保存来源视图的可恢复状态，返回恢复题目身份、有效草稿及阅读状态；正式已提交与待提交内容分开。任务已推进或来源版本变化时显示历史／失效状态，不回写旧任务。
- 切到其他课程使用该课程会话，原课会话和未保存内存保留；首版不跨课程自动混合证据。保存失败／冲突沿既有保护，快速切换不能让旧响应覆盖新视图。
- 生成中切页不等于取消服务端任务；回复仍绑定发送时上下文，不自动切回抢焦点、不写当前新页面。返回可查看状态；取消是否支持及计费边界须按真实后端能力定义。

### 最小 Agent 工具提案

| 组别 | 必要能力 | 调用与边界 |
|---|---|---|
| 读取明确上下文 | 读取已确认附件、当前有效题目公开内容、已提交作答与可见反馈 | 服务端取权威数据；不把前端文本当评分依据，不给普通对话暴露隐藏答案 |
| 课程资料检索 | 按问题在本课程有效资料中找候选证据 | 用户发起问题后在明确范围内执行，记录来源和版本，不扫描私人全盘 |
| 查看证据 | 读具体页／片段，必要时取得区域裁剪视觉输入 | 检索摘要不能冒充原文；无视觉能力明确回退，坐标不等于内容 |
| 提出定位动作 | 生成有效资料／页／区域的定位目标和返回关系 | 系统校验目标；默认点击打开，明确要求打开时可执行，不任意控制DOM或运行代码 |
| 保存学习内容 | 创建贴条、资料链接或题目↔知识关联 | 用户一次明确保存后执行，幂等去重、可撤销，不修改原件／覆盖笔记 |
| 题目帮助适配 | 沿原带学服务处理当前题、同意与帮助暴露 | 同一个侧栏承接，后台保持保护；不得通过资料检索或普通聊天绕过重测规则 |
| 网络检索（后续） | 获取并核对外部资料片段 | 实际来源可追溯，区分引用与归纳；首版不以模型编造链接代替工具 |

Agent 无需首版拥有自动提交答案、任意改分、删除资料、自由浏览器操作或任意代码执行工具。成绩／推进仍经现有显式业务操作；可以提供操作入口，但不能把聊天意图直接当正式提交。

### 一次请求的工作流提案

1. 读取用户消息、确认附件与会话，冻结输入版本和 request_id。
2. 识别本次意图，服务端检查来源有效性、题目状态、公开范围及所需同意。信息不足才追问，不强制每次问一遍。
3. 先查明确上下文和课程资料；只在有依据缺口时补读，避免重复检索和无限工具循环。设置调用／时长／token上限，耗尽时诚实说明缺口。
4. 核对证据支持程度，生成解释和受约束的引用／定位候选；模型不是写入和评分裁判。
5. 输出前再次核对来源、任务与可见性；记录回复、工具结果、状态和用量。版本变动时不直接发布过期题目帮助。
6. UI 展示解释和可操作引用，默认不改变中央视图、不自动持久化贴条。用户点击定位或保存后走确定性动作与存储回执。
7. 超时先读状态，同 request_id 不重复生成；失败保留原问题，不假报已发送或已保存。

本轮优先讨论普通练习的默认帮助体验、提交前草稿附带方式及跨页上下文呈现；独立测评保留单独可识别的规则。后续再将达成共识的部分写成独立任务与验收，不在本轮修改代码或调用模型。
