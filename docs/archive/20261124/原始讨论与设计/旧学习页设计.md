# 前端设计契约：学习会话页试点

当前设计审查入口（2026-11-24）：[产品设想与现有设计一致性审查](../实施验收与复核/20261124_产品设想与现有设计一致性审查.md)。下文为旧学习页试点，不是完整资料学习工作区的当前布局定案；长解释、中央内容关联及非线性恢复不能由本文旧框架缩小。

助手UI纠偏：普通界面只有一个助手，不展示旧带学／问题记录双模式，不要求用户启用版本或选择存储技术。历史记录保留在详情；保存失败与冲突恢复直接可达。主区聚焦问题、已确认附件及草稿，未接通真实回答时必须如实说明。兼容旧服务不等于保留旧产品入口。

2026-11-22：本文为此前的学习页设计草案。用户提出资料学习工作区与统一上下文助手需求，且未确认原先“题目居中、资料在辅助区”的布局。后续设计先读[讨论记录](2026-11-22_资料学习工作区讨论记录.md)，不得将本文旧布局作为已确认方案；具体替代设计仍在讨论。

日期：2026-11-11。状态：设计草案；不代表页面已实现或新增教学能力已可用。

## 1. 这次先解决什么

学生打开一门课后，能够清楚回答：正在处理哪一道题、现在该做什么、已经发生什么、下一步如何继续。首个试点只覆盖学习会话页，不同时重做课程、资料管理、题库和统计页面。

设计依据是现有 CurrentLearningQuestion、LearningAnswerForm、TutoringPanel、LearningOperationStatus 与会话客户端，以及独立 BoardUI 实验。借鉴源码组件、统一规则和状态验收的制作方式；主题颜色不作为设计起点。

## 2. 从一个真实任务开始

首条走通路径：进入课程 → 查看当前题 → 写下思路 → 提交正式作答 → 查看反馈 → 按现有规则进入下一步。

并行验证求助路径：查看当前题 → 围绕当前题求助 → 阅读说明与依据 → 返回正式作答。明确显示已经接受帮助及其对独立性记录的影响；独立重测求助继续遵守既有转带学规则。

首版不把两个输入框合并成含糊的“发送”。不把聊天消息当作正式提交，不把一次讲解或检查自动当作掌握证明。

## 3. 页面信息层级与线框

桌面草图：

```text
课程导航 | 当前课程 / 当前阶段 / 恢复状态
         | 当前题目与必要的来源说明 | 按需打开：带学 / 资料依据
         | 正式作答与当前主操作     |
         | 本次反馈与允许的下一步   |
```

中央是主要任务，辅助区默认不挤占阅读。桌面 1440px 可并排；820px 根据实际内容切换为单列；390px 题目和作答优先，辅助内容采用可返回的区域或面板。断点需通过长中文题干、公式和输入区验证，再固定到样式。首版不做可拖动分栏。

信息展示规则：

- 始终可见：题目、当前阶段、作答或帮助状态、可执行的主要动作、影响提交和独立性的提示。
- 操作后出现：已保存原答、判分结果、缺漏点、允许执行的下一步。
- 按需展开：质量详情、来源全文、历史与诊断依据；影响安全推进的错误不能折叠隐藏。
- 评分要点与参考答案沿用现有可见性条件，不因改版提前显示。
- 学生无需先理解内部管线和模型工程术语才能完成学习。

## 4. 先画状态，再写页面

下面是设计检查场景，不是新的后端枚举或会话状态机；实现时映射现有字段与派生条件。

| 场景 | 学生看见什么 | 页面允许什么 |
|---|---|---|
| 尚未开始 / 资料不足 | 当前缺少的条件与现有可用入口 | 按当前业务规则补资料或开始，不虚构已具备的范围 |
| 读取或生成中 | 正在执行的真实操作与等待说明 | 保留上下文，防止重复触发；无虚构进度条 |
| 等待作答 | 当前题、独立或已受帮助标记、正式输入 | 输入草稿，按权限提交或求助 |
| 提交中 | 正在保存并核对、当前草稿 | 禁止重复写入，不提前展示成功 |
| 带学中 | 当前题关联的消息、帮助记录、返回作答入口 | 按现有规则交流；发送与正式提交明确区分 |
| 已有反馈 | 服务器保存的答案、判分依据与纠错入口 | 仅显示当前业务允许的继续或补充操作 |
| 结果未知 / 恢复中 | 尚未确认保存结果，正在核对服务器 | 保留草稿，禁止盲目重发 |
| 请求失败 / 来源变化 | 原因、已保留内容与可执行恢复办法 | 重试必须遵守现有幂等和会话边界 |
| 已完成 / 被阻塞 | 当前结果与具体条件 | 不靠空按钮或无限加载让学生猜测 |

每个场景指定一个最突出操作；必要的返回、求助或纠错作为次操作。不得为了固定按钮位置显示当前不允许的业务动作。

## 5. 最小设计语言

- 先沿用现有 React、普通 CSS、Lucide 与 Markdown / 数学渲染，组件库选型不阻塞线框确认。
- 当前 paper / ink / muted / line / accent 等变量作为迁移输入。新增语义角色覆盖页面、表面、主次文字、分隔、主操作、危险、焦点和禁用；确定值集中维护，禁止页面各自硬编码。具体配色在原型阶段确认。
- 排版先固定页标题、区域标题、正文、辅助说明、代码五类；正文候选为 16px / 1.7，说明为 13–14px / 1.5，以实际题干验证。字重、行高和字距随角色定义。
- 间距基于 4px 倍数，常用 8 / 12 / 16 / 24 / 32；内容宽度优先照顾题干阅读，移动触控主操作目标高度至少 44px。
- 第一批基础件仅覆盖 Button、IconButton、Field、StatusNotice、Disclosure；出现真实浮层需求再选定 Dialog 基础方案。当前库已有控件优先复用，不并存两套同名职责。
- 现有 styles.css 与 workspace.css 存在层叠覆盖。迁移时逐块标明旧规则的替换范围并清理，禁止再叠第三套全局覆盖；不在试点中删除其他页面依赖的规则。
- 暗色与复杂动效后置。全局主题开关须覆盖正文、表单、公式与浮层后再发布。

## 6. 如何组织开发，避免交叉修改

这是前端专题的交付顺序，不新增或改写总体 PR 编号。教学规则变更继续走现有产品计划。

1. **设计交付**：本契约、一个真实长题样本、桌面 / 窄屏线框、等待作答 / 带学 / 已反馈 / 结果未知四个关键场景的可点击原型。原型数据明确标为演示。验收关注学生是否知道下一步、是否误把聊天当提交。
2. **样式与基础件交付**：固定最少设计变量和控件状态，在隔离原型验证。仅处理共享样式和基础控件，不改 API 与学习规则。引入依赖前记录它解决的实际需求、现有方案为何不足及生成代码影响。
3. **学习页接入交付**：基于已拆分组件调整呈现，复用 LearningPanel 的唯一会话编排和现有 clients。保留草稿、刷新恢复、版本、帮助记账与重测保护；不能为了视觉方便复制会话状态。
4. **验收后扩展**：学习路径通过后，再逐页迁移资料和历史。新教学反馈格式需要后端支持时单列契约变更，不能在 UI 中模拟真实能力。

同一批次尽量只设一个共享样式 / LearningPanel 集成人；其他工作先明确组件 props 和文件边界。不要同时在多个分支重写同一全局样式或会话编排器。

## 7. 验收出口

- 390 / 820 / 1440px 的长中文题、公式、代码、宽表格和长文件名；页面无横向溢出，宽内容在自身区域可滚动。
- 输入中文时回车不误提交；键盘可以到达主要动作；辅助面板关闭后焦点与阅读位置合理返回。
- 未答不泄露答案；求助影响清楚；已有原答与草稿不混淆；保存结果未知时不诱导重复提交。
- 模拟 API 覆盖四个关键场景与失败恢复；构建、相关单元和既有学习路径浏览器回归通过。
- 截图目视检查加完整路径操作，记录是否退化；视觉完成不等于教学效果已提升。

## 8. 后续实现前需要形成的判断

第一轮原型默认面向桌面复习，兼顾手机；以题目和正式作答为中心，带学作为可随时进入的辅助工作区。这是便于启动的产品假设，需用原型验证：如果主要使用情境是手机或以对话带学为主，应先调整信息层级，再推进组件接入。

对当前设计流程补充三点：

1. 在页面原型前建立组件映射：业务任务 → 页面区域 → 已有基础件 → 缺失控件 → 对应官方示例。先查真实组件 API，再组合原型，避免先自由生成一套样式后返工。
2. 将设计决定变成可执行规则：已确定的文字角色、语义变量、主次操作、状态和验收写入项目规则；组件技术专用的 cx / React Aria / Tailwind 约束只在采用该技术的范围生效。主项目是否迁移仍需单独决定。
3. 教程中的 AI chat 页面是通用组合示例，不能替代本项目的正式作答、求助后独立性、恢复和教学反馈设计。模式和组件目录用于减少实现猜测，产品路径仍由实际学习任务决定。

Skill 提供知识与规则；MCP 提供按需查源码、用例和安装的工具。本轮未配置 MCP，已通过 CLI 与下载源码完成实验，因此 MCP 不是进入原型设计的前置依赖。

## 11. FE-V02 桌面阅读工作台（2026-11-23，评审中）

此节是当前资料阅读设计输入；第1～10节保留为学习页历史草案，不作为已确认布局。任务依据 docs/development/FE-V02_电脑端资料阅读工作台设计与实现任务书.md。

### 任务与组件映射

| 用户任务 | 页面区域／状态 | 复用／组件 |
|---|---|---|
| 打开与继续阅读 | 文件栏、空／读取／失败、保存状态 | ReaderLab、PDF.js、BoardUI Button |
| 翻页与选择工具 | 导航、页码、缩放、当前模式 | PdfPage、AnnotationLayer、BoardUI Button；有限原生 select 暂保留旧核心 |
| 查看笔记 | 左栏页面／笔记切换，空／检索无结果／定位 | NotesNavigation、BoardUI Input/Label/HintText、Button |
| 批注与恢复 | 覆盖层、贴条、自动保存 | 原坐标／历史／IndexedDB；collapsed 可选字段向后兼容 |
| 选区解释与返回 | 按需右栏、草稿、演示解释、引用 | ExampleExplanation、StudyMarkdown 安全数学链路、原 jump/back |

### 两套结构与推荐

A：顶部横向阅读／批注工具，左栏在页面与笔记间切换，中央原件，右栏按需助手。优势为横向阅读面积大，代价为顶部多占48px。
B：左侧84～96px竖工具轨，页面／笔记导航在工具右侧，中央原件，右侧助手。优势为频繁批注时工具位置固定，代价为横向阅读减少84～96px，窄桌面可收起导航。

推荐A，尚未得到用户确认。评审入口 /reader-workbench.html，按钮切换仅变展示，不卸载阅读器。1440×900、1024×768、1920×1080可操作；三状态截图在 FE-V02 报告所列证据目录。评审后删除非选定结构，不能长期维护 A/B 产品开关。

### 集中语言与适配

workbench.css 为独立入口样式，不导入旧 styles.css/workspace.css/reader.css。page-layers.css只复用PDF文字层与坐标几何。颜色角色 wb-surface/muted/ground/ink/secondary/line/accent/selected/danger/focus 映射BoardUI语义变量；纸张和笔记颜色为集中内容角色。字体为系统中文回退；标题16、正文14、辅助11～12，统一行高；PDF内字号不改。间距4/8/12/16/24，分隔1px、控件圆角6px，课件保持连续工作区，不使用大卡片装饰。

导航204px，窄桌面164px；助手344px，窄桌面300px。工具不换成多行，必要时工具栏内部横滚；阅读、导航和助手各自滚动。用户显式比例不随开关改变，fit模式随可用宽度更新。内部顶部渐隐只在scrollTop>0时启用。工具、关闭与问题输入固定可达。reduced-motion禁用动效。

BoardUI Button与Input实际源码仅改局部导入；隔离路径 ../boardui 不使用全站 @/别名，以免改主工程解析。输入API按实际源码使用，CSS扫描所有使用组件。存储范围在文件栏持续可见，详细限制在保存说明；故障仅?dev=1。新笔色只影响后续笔画。
