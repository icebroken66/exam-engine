## 1. 产品原则

- 当前页面不等于学习目标。题做到一半打开课件，原题保持未完成，资料可以是原任务的查阅支线。
- 页面停留时长不能证明用户正在看什么、已理解、已完成或放弃。纸上作答在用户上传／说明前不可观测；系统显示未知，不伪装持续监控。
- 知道当前视图的课程／资料／题目身份，不等于已获准读取选区、纸笔照片、笔记或草稿。用户从助手内明确附带内容；普通高亮不是 AI 指令。
- 模型提出解释／候选意图，服务端持有任务身份、版本、可见性和写入权限。学习状态不依赖模型从聊天中自行回忆。

## 2. 六种状态分离

| 状态 | 必要信息与作用 |
|---|---|
| 学习任务 | task ID、课程、平台题或外部纸题身份、阶段、active／waiting_user／paused／completed；用户目标及服务端版本 |
| 当前界面 | 当前课程、视图、资料／题目、页、缩放、滚动；仅供导航恢复 |
| 查阅支线 | parent task、查阅原因（用户明确／引用跳转／未知）、原视图书签、返回目标；最多先一层 |
| 讨论主题 | conversation／topic ID、所属任务、当前附件和相关消息；应用只有一个助手入口，内部可隔离主题 |
| 多模态附件 | 原文件 hash、媒体类型、页／区域、用户说明、上传／转录版本与未确认部分 |
| 生成请求 | request ID、冻结的 task/context 版本、工具记录、状态、结果／用量；不写入客户端任意可编辑快照冒充权威 |

这些是语义职责，不要求首版建六张表。优先与既有 LearningSession／LearningTask、助手快照、reader快照、UsageRecord 和带学记录建立映射，外部题与对话请求确需新增才扩模型。

## 3. 中断与恢复规则

1. 做题时按引用跳到资料：创建带 parent task 的查阅支线，原题保持 active／waiting_user，不因为路由切换而完成或切到新题。展示“正在为第X题查资料／返回本题”。
2. 手动打开资料：保留原未完成任务，当前导航原因标未知；不每次弹窗。发出歧义问题或要正式开始新任务时，才问“继续围绕原题，还是单独学习这份资料？”
3. 长时间停留：不据此改变任务。返回时给简短可恢复摘要，默认静默保持；可选提醒仅在用户愿意时设计，不建基于停留时间的掌握判断。
4. 用户明确暂放原题：标 paused，保存书签与已有草稿；明确开始另一题时换主任务，旧题进入可恢复列表。恢复前重新检查任务／来源版本。
5. 用户在纸上做题：选择“纸上作答”只表示等待用户，不自动判分、不持续调用模型。可以上传拍照、说明卡点或稍后继续。照片是未核实作答证据，不自动等于正式提交。
6. 用户上传外部试题：创建有明确身份的外部题任务，允许题目图和作答图分开。没有平台正式评分契约时只提供辅助分析，不伪造平台成绩或已完成记录。
7. 生成中换题：旧请求继续归旧任务；不取消假报成功，不把其回复塞进新题输入上下文或弹回原页。完成后提示旧主题有回复，用户可点回。来源／题目版本变化时在发布前复核，必要时标过期不可用于当前指导。

## 4. 题目之间的上下文边界

- 每题有 task scope；新题默认不继承上题照片、选项、草稿、局部解法和工具结果。旧记录可查看，但不自动当新题依据。
- 每次发送由服务端构建上下文包：当前目标、题目身份和版本、当前消息、用户确认附件、本主题必要对话、有效查阅证据、必要学习规则。设置预算，不能直接把全课聊天全塞入。
- 可复用经过来源核查的概念解释／用户明确偏好，保留 provenance；关于错误／能力的模型猜测仍是待确认，不永久贴标签。摘要不替代原始附件／任务身份，题切换清理短期材料，不删除历史。
- 当前题没有变但用户改纸上答案：新照片形成新版本，原图保留。没有明确替换／比较意图时先确认本次照片角色，不把前后两稿混成一份。
- 助手以轻量状态展示“目标：第X题；当前：课件第Y页；附件：作答照片V2”，差异明显时提示，不堆技术 ID 或每次重复确认。

## 5. 多模态输入与证据

- 文字PDF：同时保留文字及版面位置，图表／公式／版面相关问题读取页图或区域；不能因为有文字层就认定图片内容已理解。
- PPTX：当前人工转换PDF限制保留，原件至预览映射及字体保真需验证；后续自动转换独立实现，不宣称模型直接可靠理解全部PPT动画／对象。
- 纸笔照片：上传预览、旋转／裁剪、题目／作答角色及所属任务；提取可读步骤并标出模糊符号，关键不确定处请用户确认／补拍。模型支持视觉不等于已验证复杂手写、几何图和公式正确率。
- 使用实际图像内容，不只传坐标或文件名；保留原图与裁剪坐标、hash、转录版本。预处理不覆盖原图。附件可按题目与多张连续作答排序，数量／尺寸／预算由后续任务书确定。
- 学生照片属于用户作答证据，不属于正确答案来源；课件属于课程依据；外部检索属于补充来源，类型不可混淆。普通聊天不能读取尚未公开的教师答案。
- 图像问题若只传选区不够理解可补同页范围，但先遵守已说明的取材范围与预算。看不清时不编造符号，更不能高置信评分。

## 6. 最小工具与权限

| 工具职责 | 行为边界 |
|---|---|
| 读取任务快照 | 权威当前任务、规则、公开题干及可见反馈，不由模型直接改状态 |
| 读取确认附件 | 获取原图／裁剪／文字和来源；禁止按任意本机路径读文件 |
| 课程检索与证据补读 | 范围受课程／版本约束，必要时查看原页或图像；记录哪些已读／未读 |
| 查看纸笔步骤 | 视觉理解与可选OCR／转录，输出不确定点；先确定角色再分析 |
| 提出导航／返回动作 | 有类型的目标ID／页／区域，服务端校验；默认点击或明确打开指令才切页 |
| 保存笔记与双向关联 | 明确保存后幂等写入，可撤销，原件不改，双向显示用同一关系 |
| 暂停／恢复学习任务 | 显式用户意图经确定性接口执行；普通路由切换不触发新主任务 |
| 题内帮助适配 | 复用同意、帮助记录、版本保护；与原带学服务逐步合流，不复制规则 |
| 网络检索（后置） | 获取实际来源与支持片段；不得凭模型记忆伪造链接 |

工具按需求开放，首版一个多模态导师加确定性编排器即可；不因参考多Agent框架就引入多个自治代理。正式提交、评分纠错和推进继续由现有显式操作执行。

## 7. 请求执行工作流

用户消息／照片／明确动作 → 冻结 request/task/context 版本 → 校验角色与独立性／来源 → 判断是否需要澄清 → 按需检索／读页图／读作答图 → 核对关键识别与证据 → 解释及有类型的引用／动作候选 → 发布前复核 → 保存回复与用量 → 用户选择定位／保存／继续作答。

- 模型推理不替代确定性状态检查。独立重测的相关帮助在实际提供前按规则转带学；资料支线或纸图入口不能绕过，也不能把普通资料阅读一律记帮助。
- checkpoint 至少覆盖已接受请求、已构建证据、生成结果待复核、已发布。重启恢复读取状态；非幂等副作用独立记账，不重放整段工具链。
- request ID 负责本系统去重；上游超时是否已计费／执行可能未知，不能承诺跨供应商绝对exactly-once。状态未知先重读，不自动重复付费请求，明确单API进程边界。
- 不因页面滚动／选项勾选／停留时间每次调用模型。导航事件以轻量结构保存；模型只在提问或明确学习动作时使用必要状态。
- 工具调用、时长、图像和token预算有界；不够时报告限制。取消、重试和资料版本变化都有明确状态，不把取消前端请求当作已取消模型计费。

## 8. 开源机制参考与采用判断

2026-11-23 在线核对以下官方文档；只阅读机制与示例，未声称完成源码审计或框架安装。

- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分线程级 checkpoint 与跨线程 store。本项目借鉴任务／请求检查点与可追溯长期记录分离，不等同于无边界保存聊天。
- [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)：参考挂起、外部输入和恢复机制；学习任务暂停与模型运行挂起是两种状态，不直接混用。
- [AutoGen Agents](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/agents.html)：参考 MultiModalMessage 与受限模型上下文。限制最近N条消息不能解决题目归属，仍须本项目按task scope组装上下文。
- [LlamaIndex CitationQueryEngine](https://developers.llamaindex.ai/python/examples/query_engine/citation_query_engine/)：参考带来源节点的引用回答；不将自动引用当真值验证，也不直接提供PDF页内精确框，需保留原页映射。

建议先在既有 FastAPI／SQLAlchemy／SQLite／模型网关中实现小型状态编排和明确类型，再通过恢复复杂度、维护成本决定是否采用 LangGraph。框架名称不作为交付物，不因本草案迁移全部后端。

## 9. 与现有代码的关系

模型网关已有 VisionImage 和图像请求入口，视觉解析已有PDF整页渲染与图片预处理；这些可复用，但目前主要服务资料转录，不代表统一助手已支持纸笔照片、附件生命周期及真实多模态发送。统一助手当前 context 仍主要是单个 document／question／answer对象，缺少外部纸题、附件版本与主任务／支线表达。

现有 reader／assistant 快照和带学记录可作基础，但客户端可编辑JSON快照不能成为生成回复、工具结果或帮助权限的权威来源。下一任务需定义旧数据兼容、生成表／状态、上下文选择与恢复接口，而非只增加一个图片上传按钮。

## 10. 必须通过的情景（未来任务书输入）

1. 纸上做平台题，上传半页解答，看不清负号时先核实，不捏造步骤或自动提交。
2. 做题中按引用去查资料，长时间后返回，原题与草稿／照片仍归原任务，不被自动完成。
3. 手动看资料时问“这个为什么”，若指代不清才澄清；不自作主张继续原题，也不遗忘原任务。
4. 第1题回复生成中切第2题，旧回复归原主题，新题无旧照片／解法污染。
5. 用户明确暂停第1题开始新题，能恢复原题；题目已变化时不把旧草稿写回新版本。
6. 上传外部题图与作答图、多张连续纸稿及改写版本，角色和顺序正确，不产生伪平台成绩。
7. 独立重测经资料／照片／普通聊天求助仍正确执行同意和帮助规则，不一律阻断无关操作问题。
8. 刷新／后端重启／超时／丢回执，不重复请求模型或写重复笔记；明确未知执行状态。
9. 选区仅为个人标记不进入附件；在助手内取消取材不改笔记或旧上下文。
10. 来源移除或hash变化，旧引用可追溯但不作为当前有效依据；图像定位缺乏证据时降到页级。

下一步应先由用户评审主任务／支线与纸笔拍照路径，再拆“状态与上下文契约 → 多模态发送与证据 → 定位／保存动作”的有限实施任务。前端须同步展示任务与上下文，不能先造一个全能代理黑盒。


## 11. 修订：非线性学习、按需多 Agent 与 Harness

2026-11-23，用户质疑完整流程是否常态，并提出多Agent合作是否更适合及“hamness”概念。本轮网络核查后推测所指为 Harness，尚不排除用户指某个同名具体项目。

### 非线性任务模型

完整路径用于端到端验收，不作为用户必须执行的流水线。交互按事件驱动：提问、附图、翻页、切课程、主动开始／暂停／恢复任务、提交／纠错等事件更新有版本状态。只有显式学习动作改变任务状态，导航只更新视图；不确定的目标关系由模型提出候选或在必要时询问。

不强制每个用户同时只能有一个学习任务。可保留多个未完成任务，每个有状态与书签；当前明确目标可为空，问题也可独立于任何题目。关联资料查阅可以连接某任务，也可是一段独立探索。用户可改变关联，不以栈式一步返回强迫其原路完成。首版导航可先实现一次返回，但数据关系不可把未来交叉引用锁死为固定线性步骤。

### 多Agent候选：一个对话负责人，按需委派

- 对话导师负责用户表达、教学策略、澄清和最终回应，是稳定前台接口，不独占权威状态。
- 多模态判读子任务：复杂纸稿／图表时返回可读步骤、空间锚点与不确定处。若一个视觉模型调用已足够则作为工具调用，不为了命名Agent增加循环。
- 证据研究子任务：需比较多份资料／多个来源时独立检索补读，返回证据及支持／冲突点；可在问题已明确时与图像判读并行。证据查询依赖识别结果时必须顺序。
- 核查子任务：高风险公式推导、评分异议或来源冲突时调用；优先可执行计算与原始来源验证，第二个模型意见不自动视为真。
- 多角色只是逻辑分工；只有具备独立上下文、目标、工具和有界执行循环的子任务才按子Agent管理。避免把每次格式转换／保存都变成Agent。

每个委派包包含request_id、课程／任务／主题及版本、明确目标、授权附件／证据、输出契约与预算。返回必须携带来源与不确定性，由对话导师整合并由Harness校验；禁止子Agent互相随意改全局目标、互写学生画像或发布到错误任务。普通短解释可直接回应，不每条消息唤醒全队。具体路由与增益需要评测，不因用户讨论多Agent即启动开发子代理。

### Harness的职责

Harness是模型外的软件运行与控制支撑，包括模型／工具执行循环、上下文构建、状态持久化、权限／来源校验、预算、幂等和恢复、可观测日志及评估。它既可承载单Agent，也可承载多Agent，不与多Agent二选一，不等于某个框架或一段更长的提示词。

本项目可称学习Agent Harness：事件与版本状态是事实底座，模型可以提出如何教、查什么、是否委派，代码限制读取／写入范围与状态生效。Harness保留多个未完成任务和上下文关系，不凭页面停留猜意图；单Agent变多Agent仍不能替代这层。

### 对比验收建议

先在相同任务集、模型条件和预算约束下比较：多模态导师＋检索工具，与导师按需委派判读／研究／核查。报告跨题污染、关键符号识别／澄清、证据支持、切换恢复、回答延迟、调用／token成本及失败传播，不预设多Agent必胜，也不拿研究系统的收益数字当教学收益。

## 12. 设计立场：用户自由行动，系统维护事实，导师按需协作（待讨论）

本轮用户要求展开说明想法，以下为代理观点，不代表用户确认，也不自动创建实现任务。

- 主要目标是减少用户整理上下文与恢复任务的负担，不追求尽可能多的Agent。保留多个未完成任务／独立探索，按显式意图和可核实事件维护关系。
- AI可提出“当前问题可能承接原题”的候选解释，系统保留推断依据与不确定性；不将推断静默升级成用户意图、成绩或永久画像。当前视图身份可作为轻量线索，页面内容与私人草稿／图片仍按明确附件授权。
- 低影响动作可按本次问题自动执行：在已说明范围内检索课程资料、读取已附带图像、补读检索证据。定位默认用可点击入口，用户明确要求打开时可执行；改变学习目标、提交／改分、长期写笔记等需要相应明确操作。
- 新题隔离题干实例、用户答案、照片与局部推导，但允许明确关联的比较问题和来源可核查的概念知识跨题复用。不能简单清空历史，也不能把所有历史交给每个专家。
- 用户是否仍在纸上推导属于不可观测事实，页面停留不改变任务。系统承担保留恢复点，用户不必每次导航登记暂停；只有下一步决策依赖不确定目标时再澄清。
- 前台只有一个稳定导师。多模态判读、跨资料研究、独立核查可为按需专家，输出结构化证据／疑点，不直接对用户各说各话。角色可先实现为工具封装，仅在独立上下文／多步执行确有价值时升级为子Agent；避免共享一个巨型可变上下文。
- Harness承接任务／上下文关联图、范围化上下文构建、请求持久状态、工具权限、预算和回执。先定义这层契约，再决定具体框架及多Agent数量。
- 来源、状态和证据不确定性在适当位置可见，但不把界面做成多模式控制台。普通问题无需展示内部专家列表或推理过程。用户纠正目标／图片角色时修订关联，保留原历史，旧回复不当作新目标答案。
- 建议下一交付是少量非线性情景与状态／工具契约的设计评审：题目→独立概念→恢复、两题对比、旧请求返回时已换题、纸稿版本替换、手动切课件但无明确任务。案例用于找冲突，不规定用户流程。


## 13. 用户认可架构方向

用户在上一轮观点说明后回复“我认为你的思路是可以的”。认可的方向为：非线性学习与多个未完成任务；当前页面与讨论主题分离；统一导师面向用户、按需专家协作；委派使用范围明确的任务包；Harness维护任务、上下文、版本、请求恢复及写入边界；按动作影响决定自动执行、提议或明确确认。

这是方向认可，不代表每项细节或框架选型定稿，也不等于授权开始实现、调用真实模型或新增开发任务。专家实际启用条件、工具输入输出、状态／附件数据契约、权限与独立性、成本预算和验收阈值仍需形成可审阅方案。

下一步建议先完成非线性情景决策表，逐项确定“系统知道什么／不知道什么、是否澄清、允许读取范围、状态变化、恢复与副作用”；据此编写状态与上下文契约，再拆有限实现任务。用户无需再重复确认已认可方向。
