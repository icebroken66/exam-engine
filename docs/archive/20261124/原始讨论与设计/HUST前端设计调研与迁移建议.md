# HUST 前端设计调研与迁移建议

# 时效说明（2026-11-24）

本文是早期前端参考研究。关于“题目居中／资料辅助”、手机开发范围及迁移顺序的旧建议不代表用户最新定案；以[讨论记录](2026-11-22_资料学习工作区讨论记录.md)、FE-V07／09及[当前设计一致性审查](../实施验收与复核/20261124_产品设想与现有设计一致性审查.md)为准。组件与来源研究仍可作为参考，不能据此恢复旧产品布局。

日期：2026-11-10。状态：研究与迁移建议，未实施 UI 改造。以用户提供的本地 HUST-CSAgent 为研究对象，不修改该仓库，不触及正式课程和学习记录。

## 1. 结论

值得学习的是“明确设计规范 → 发现真实组件 → 统一适配 → 组合页面 → 验证状态”的制作方法，而不只是配色、圆角或动效。Exam Engine 可以使用同样的方法建立自己的学习工作台，不需要复制 HUST 的会话运行时、全部三栏、账户系统或前端依赖。

本次读取本地设计文档、工程约束、BoardUI skill、主题和组件实现、主题浏览器测试；对照本项目 CSS、学习组件与依赖。曾尝试访问官方安装页，但未取得可读正文；组件安装和 Pro 边界以本地 skill / README 为本次证据，实施前须再核对官方当前资料。没有启动 HUST 应用、检查其运行截图或执行它的测试，因此本文判断是文档 / 源码分析，不能宣称当前页面全部符合规范或迁移效果已验证。

## 2. 本地证据与制作流程

源仓库：`D:/HUSTagent/HUSTagent/HUST-CSAgent`。下列路径均相对于该目录。

| 来源 | 实际发现 | 对我们的意义 |
|---|---|---|
| design.md，尤其 Layout / Components / 工程应用 / 文案精简 | YAML 保存确定值，正文定义用途、例外、布局、响应式、必要状态与验收 | 建立项目专用设计契约，不能只用“简洁现代”提示生成页面 |
| apps/web/AGENTS.md | 业务组件按 feature 就近组织，现有组件优先，不重复状态和整套工作台 | 与刚完成的前端拆分相结合，不重新耦合接口和 UI |
| .agents/skills/boardui/SKILL.md 与 references | 发现组件、复用源码、语义 token、组合排版、主题与页面模式 | 学制作流程；该 skill 的 Next.js / Tailwind 假设不能原样成为本项目规则 |
| apps/web/src/globals.css、public/theme.js | 全局样式与首屏主题解析；系统 / 手动偏好、跨页主题一致 | 样式从共享层生效；如做暗色，必须同时覆盖浮层和首屏 |
| views/boardui-chat-starter-preview/preview-ui.tsx | 共享表面变量、按钮 / Tooltip 包装、Portal 的主题映射 | 组件需要统一默认值、焦点与浮层归属，不只统一颜色 |
| components/ui/button.tsx | variant / size / surface 定义共同交互，复用底层语义 | 在本项目建立少量稳定基础件，减少各面板重复样式 |
| BoardUiChatStarterPreview.tsx、RightPanel.tsx | 任务与补充工作区分离；窄屏 Dialog、面板关闭后焦点返回、按面板宽度调整 Tab | 学任务优先和渐进呈现，不能为三栏而填充无用信息 |
| test/system-theme.browser.test.mjs、设计中的检查矩阵 | 测实际 color-scheme、计算样式与状态，而不只检查类名 | 新页面按可操作状态验收，旧测试结果不自动转移 |

参考设计本身也有边界：本地 README 明确区分参考复刻、免费动效和 Pro / 素材权限；局部代码仍有大量自定义类与主题映射，不能把整仓当成零成本通用组件库。设计中“所有菜单自定义”“代码使用同一字体”等是其项目取舍，不是我们必须继承的原则。

## 3. 应借鉴和应调整的部分

| 做法 | 建议 | 适配边界 |
|---|---|---|
| 灰阶表面、单主色、统一间距和字体层级 | 采用 | 先保留现有绿色体系，用少量语义 token 控制，颜色值在设计阶段确认 |
| 一屏一个主任务，辅助信息渐进展示 | 优先采用 | 题目和正式作答是核心，来源 / 历史按需展开；错误与独立性后果不能藏入帮助 |
| 基础控件统一 variant 和状态 | 采用 | 先 Button、IconButton、Field、状态、Disclosure；仅在需要浮层时选菜单 / Dialog 基础件 |
| 图标工具、文字主操作 | 有选择采用 | 上传 / 刷新可用图标和可访问名称；提交作答、求助转带学、重测、删除保留明确文字 |
| 三栏与可拖动面板 | 先试点再决定 | 宽屏可显示资料区，窄屏用可关闭面板；首版不做拖拽和多重固定区 |
| 明暗主题、首屏无闪烁 | 可独立排期 | 不在只完成局部暗色时提供全局暗色开关 |
| 动效 | 后置 | 先改善层级和路径，再增加轻反馈；不循环假装思考、不模拟进度或流式输出 |
| Tailwind / SWR / Router / motion 等整套依赖 | 不整体迁移 | 当前普通 CSS 和请求层可保留；每个新增包要对应实际需求 |
| 用源项目组件和素材 | 逐项审查 | 本地存在不等于可以跨项目分发，保留许可 / 来源；不复制 Pro 模板和参考素材 |

本项目 workspace.css 已有 paper / ink / accent 等变量，但仍有分散颜色、字号和重复覆盖；当前学习页面还承载题目、作答、交流、依据与学习状态。优先把这些内容按任务重新分层，不能只再叠一层覆盖 CSS。

## 4. 推荐的学习页试点

桌面：左侧课程 / 功能导航，中央当前题与正式作答，右侧按需打开带学或资料依据。右侧关闭时中央回收空间；是否并排常驻取决于实际中文题干、表格、公式和可用宽度，不照抄 410px。

手机：主任务单列，题目 / 正式作答入口始终易找；带学和依据通过明确入口切换或打开可关闭面板。保留草稿、关闭后焦点与返回位置，软键盘和输入区不遮挡题目 / 提交。带学不是正式作答，两个输入框不能合并成含糊的发送动作。

首版只改变呈现和导航，不改诊断、提示记账、评分、掌握和下一题规则。使用真实 API 契约或明确标为夹具的状态，不把设计样例当真实进度。

## 5. 迁移拆分（候选，不自动取代教学主线）

这些是 UI 专题内的候选批次，不是另建一套总体 PR 编号；正式排期前在本地 PR 清单只增加所选批次。

1. **设计契约和一个页面方案。** 为 Exam Engine 写 design.md：语义色、排版、间距、圆角、主次操作、学习页信息层级、响应式、所有必要状态和明确例外。准备学习页宽 / 窄布局及长题、错误、重测求助示例。验收：方案可审阅，评分和帮助后果可见，确定采用现有 CSS 还是按需引入组件；不改变业务。
2. **基础样式与控件试点。** 用共享 token 和必要基础件迁移一个学习页。旧规则有映射和删除范围，禁止通过第三套全局 CSS 掩盖冲突；不同时重做全部页面。若采用 BoardUI，先试一个免费组件，审查生成文件 / 依赖 / 许可 / 全局重置影响，不能直接全项目 init。
3. **学习工作台。** 在已拆分的 CurrentLearningQuestion / LearningAnswerForm / TutoringPanel 等组件上组合，复用现有客户端；增加资料 / 带学辅助区、窄屏返回和焦点，不复制数据状态。保留全部既有恢复和重测保护。
4. **扩展与可选主题。** 学习路径验证后迁移资料、历史与覆盖台账；主题和动效如有需要再单独实现，不成为开始教学迭代的前置。

产品方案 PR-08 可以同步准备；UI 行为改造与教学规则 PR-09 不在同一实现 PR 混改。视觉整理完成不计为教学效果提升。

## 6. 验收与来源

至少检查 390 / 820 / 1440px，必要时加 1920px：长中文题干、公式、代码、宽表格、长文件名、空 / 加载 / 失败 / 重试、保存结果未知、来源不可用、重测转带学、已判分和历史恢复。检查键盘 / 中文输入、焦点、触控目标、对比度、减少动态效果和页面横向溢出。若有暗色，所有场景同时检查浮层和正文。

除构建 / 单元 / 模拟浏览器回归，还需真实浏览器截图目视与完整路径：打开课程 → 当前题 → 正式作答 / 带学 → 引用 → 返回 → 刷新恢复。记录原有交互是否退化与主要操作是否更易找到，不凭截图判断教学更好。

## 7. 工程依赖如何协作：第二轮源码核查

本轮补查了 package-lock.json、Vite / TS / shadcn 配置、main.tsx、主题启动脚本、共享 Button / Dialog、cn、usePiChat、PreviewMotion 与 ComposerLoader。没有安装包、修改 HUST 或调用它的模型服务。外部搜索未返回可读资料，以下是本地快照事实，不保证上游当前版本。

### 源码安装，而非单一运行时组件包

本地 package-lock 中没有 boardui 包，也没有 react-aria-components；存在 shadcn 风格的本地组件、Radix、Tailwind 与 Motion。BoardUI 本地 skill 是给开发代理的组件发现 / 安装 / 组合规则；CLI 或 registry 是开发阶段取得源码的工具，不是每次打开网页时调用的服务。源码和 npm 依赖进入项目后，由 Vite 构建随应用运行。

因此需要区分三件事：BoardUI 官方安装方式、本地 skill 的通用假设、HUST 实际适配。skill 提到的 React Aria、cx、目录规则没有被整套原样采用；HUST 的现有 Radix / cn / 主题映射是实际落地。不能凭 skill 反推项目使用了所有官方依赖。

### 依赖分工

| 层 | HUST 的实际依赖 / 源码 | 工作方式 |
|---|---|---|
| 构建 | Vite、React plugin、@tailwindcss/vite | 编译 JSX 和按扫描到的工具类生成 CSS；浏览器不执行 Tailwind 编译器 |
| 主题 | globals.css、theme.js、previewStyle | CSS 语义变量映射工具类；React 前解析主题，Portal 继承全局或显式映射的主题 |
| 基础交互 | @radix-ui/react-dialog / menu / tooltip / tabs 等 | 提供状态、Portal、焦点 / 键盘等机制；本地组件包上样式和业务语义，仍需实际测试 |
| 组件变体 | class-variance-authority | 将 variant / size 等参数映射为统一类名组合；不是运行时 CSS 引擎 |
| 条件与冲突 | clsx + tailwind-merge，包装为 cn | clsx 整理条件类，twMerge 合并识别到的 Tailwind 类冲突；不负责所有自定义 CSS 层叠冲突 |
| 动画 | motion/react + CSS + 浏览器动画 API | 面板进出 / 折叠由 Motion，光带 keyframes 用 CSS，主题 reveal 用 View Transitions / animate；不是全由 Motion 负责 |
| 读数据 | SWR + apiClient | 会话列表 / 快照缓存与更新；不是 BoardUI 自带后端或 Agent 能力 |
| 实时与写入 | usePiChat、getStream、commands POST | 流读取快照更新 SWR，操作发送命令，组件只显示真实状态 |
| 内容 | react-markdown、remark / rehype、KaTeX；字体 / 图标 | 将消息转可读内容，与控件基础设施分工；我们已有相应 Markdown / 数学链路 |

### 一次按钮和弹层怎样工作

调用方传入 Button 的 variant / size / disabled / onClick → cva 选基础类和变体 → cn 合并自定义类 → React 渲染原生 button（或 Slot 的子元素）→ 点击执行业务回调。globals.css 根据语义 token 和 data 属性定义表面、主题与状态。按钮默认 type=button，防止无意提交表单。

打开 Dialog 时，Radix 管 open 状态、Portal 和焦点机制，本地 DialogContent 提供布局 / 遮罩 / 关闭按钮。元素通过 Portal 放到常规父容器之外，局部 CSS 变量可能不再继承，所以 previewStyle 显式传入主题。这解释了为什么“只改页面底色”无法自动正确适配所有浮层。

本次在源项目已有依赖中运行无网络的小型类合并实验：cn 所用的 twMerge 将 px-4 py-2 与 px-2 合并为 py-2 px-2；cva 的 primary 变体加调用方 px-6 得到 inline-flex bg-primary px-6。只验证类工具的实际行为，不是界面验收。

### 一次真实消息怎样进入界面

ChatComposer 调用业务 command → usePiChat 经 apiClient POST 带 requestId 的命令 → 服务器处理 → getStream 读取 events 的 data 帧 → snapshot 更新 SWR（revalidate=false）→ PiMessageFeed / PiActivity / 面板按新快照渲染。pending 表示请求等待，快照里的任务状态表示服务端运行，两者不能混为一个“正在思考”标志。

流断开后 hook 重连；切换 / 卸载 abort 的是前端订阅，不能据此认为服务器任务已取消。视觉依赖不提供命令幂等、教学评分或服务端取消，这些由业务协议承担。我们迁移 UI 时继续保留现有带学保存 / 重读 / 独立性规则，不能照搬这条 Pi 协议。

### 对 Exam Engine 的修正建议

上一轮“不整体迁移技术栈”并不等于这些依赖不值得采用。Tailwind + Radix + cva / cn + 源码组件是一条值得做小试点的工程路线：设计变量、可靠交互与可维护组件可以一起获得。

建议先选 Button 和一个实际需要的 Dialog / Sheet：核对可复用许可，按组件实际依赖接入，验证主题、焦点、禁用、表单和窄屏，再判断是否扩展。若选择 Tailwind v4，独立处理 Vite 插件、主题入口、preflight 与旧 CSS 冲突以及类扫描；不要把全局样式迁移藏在按钮 PR。

SWR、Router、Motion 不必为采用 BoardUI 一次全加：读缓存需求、路由需求、动画需求分别决定。尤其不能因 SWR 的自动重新验证或 UI 重试而重新 POST 带学生成 / 正式提交。动画可以在真实状态契约稳定后再接。

这轮只明确工作机制和候选工程路线；未对本项目安装或构建验证这套组合，包体、样式兼容和学习交互是否改善均待试点。
