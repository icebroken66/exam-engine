# 技术研究摘要

整理：2026-11-08。合并原 DeepTutor、准确性、证据库、理解层和语义覆盖研究。研究建议不表示已经实现；完整原文、参考链接与实验附件见 [旧档](../../../../../Exam_Engine_Docs/archive/2026-11-08_旧文档与附件.zip)。

## 1. 证据库与轻量架构

保留不可变原件、页 / 章节 / 结构块证据，以及题目、摘要和学习行动的血缘。稳定 ID 支撑引用、修订与来源移除。结构化题目按题查询，解释按证据检索，全覆盖任务按章节清单读取，不能只靠向量 top-k。

SQLite、结构化查询和现有检索先服务小规模本地课程。向量、重排、图结构或外部平台只有在真实失败样本证明收益后再加，不能因平台功能多便整体搬入。

## 2. 解析、语义与覆盖

解析回答“页面读出了什么”，语义理解回答“在课程中表示什么”，覆盖对账回答“哪些应处理单元尚无可靠结果”。摘要是压缩，检索是相关，都不能证明完整理解。

逐步保留定义、前提、公式、方法、例题、反例、考试指令，以及先修、包含、条件、例证、冲突关系。先做台账和必要关系，不预建庞大本体。长资料按章节公平分配预算，跨页题与图表保留上下文；每个单元有处理去向与失败 / 排除原因。

重点反例包括后半章节、跨页公式、表格、近重复但内容不同的课件和教师“不考”指令。文本提取成功、摘要流畅不代表这些内容已经理解。

## 3. 多模态与冲突

文本 PDF 也可能丢嵌入公式、图形和表格；有文本不意味着无需视觉检查。转录可以补充，但遮挡、手写与排版仍可能产生不同结果，需要回原图、编辑与未确认隔离。

知识正确性和课程一致性分开。不同课件、教师说明和教材要限定课程、学期、符号与条件，不能用一个可靠性分数替代。文件角色可多标签，同一 PDF 可能混有课件和练习。

## 4. 外部学习 Agent 的借鉴

- 弱点状态与证据持久化，一次答对不能关闭全部薄弱点。
- 出题、求解与验收分离，失败候选隔离；独立验收不保证绝对正确。
- 确定性与等价规则优先，模型补充开放题判分。
- 先修缺口、讲解失效与提示依赖改变后续行动。
- 工具和技能的输入、输出、条件与质量约束可检查。
- 模拟学生用于流程和边界验证，不能替代真人学习收益。

不直接照搬多 Agent 拓扑、记忆森林和多渠道系统。DeepTutor 等项目的阈值、公式和评测结果须按本项目数据校准，旧研究具体数字不是强制标准。

## 5. 分层评价

| 层次 | 核查问题 |
|---|---|
| 解析 | 符号、公式、表格、页码是否还原 |
| 结构化 | 题界、子题、选项、答案来源、去重是否正确 |
| 语义来源 | 引用支持结论吗，考点具体吗，课程范围匹配吗 |
| 覆盖 | 后续章节、低频主题、未处理单元是否保留 |
| 判分 | 人工依据一致吗，等价答案与部分得分公平吗 |
| 状态调度 | 提示、重复提交、误判和旧证据是否污染判断 |
| 学习收益 | 真人隔天能否独立完成未见题，是否省时间 |

每层保留人工小型对照与失败案例。页面成功、引用格式正确、模型高置信或生成数量，均不能替代这些评价。

## 7. 2026-11-09：教学交互开源源码复查

本轮通过 GitHub 搜索、仓库树与固定提交的源码读取，检查 DeepTutor、OpenTutor、OATutor。没有启动这些项目，没有执行下载代码，没有真实学生对照实验，不能据此声称它们教学效果优于本项目。不是只根据 README 选型，也不以 stars 或框架数量判断教学能力。

### 7.1 DeepTutor：自由带学与确定性落账分离

仓库：[HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)。检查提交 `60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db`，GitHub 元数据许可证 Apache-2.0；如复制代码仍需核对具体文件与许可证要求。

主要源码：

- [mastery_loop.yaml](https://github.com/HKUDS/DeepTutor/blob/60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db/deeptutor/capabilities/mastery/prompts/zh/mastery_loop.yaml)：学生提问、追问和异议可以直接回应，并非每轮都必须出题；待答题可以保持打开，讨论本身不改变评分。状态和掌握门槛由工具持有，允许正规推迟与无效题修复。
- [tools.py](https://github.com/HKUDS/DeepTutor/blob/60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db/deeptutor/capabilities/mastery/tools.py)：有记录实际讲解的工具，并校验当前路径、会话和轮次。讲过不等于考过，更不等于掌握。
- [test_mastery_teaching_delivery.py](https://github.com/HKUDS/DeepTutor/blob/60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db/tests/capabilities/test_mastery_teaching_delivery.py)：覆盖尚未发生的讲解不能登记、其他作用域内容不能冒充本轮交付、旧自报讲解不视为已验证。
- [test_mastery_teaching_compass.py](https://github.com/HKUDS/DeepTutor/blob/60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db/tests/capabilities/test_mastery_teaching_compass.py)：教学偏好与观察保留依据，和评分 / 掌握证据分开。测试存在不代表本轮已经运行通过。

可借鉴：保留现有状态和质量门禁，在其上允许围绕当前目标自由追问、讲解、检查；正式提交答案、提示使用、评分与掌握更新必须有独立动作。不要把每条学生消息当成答案，也不要要求每轮必须以出题结束。

不照搬：完整通用 Agent runtime、大平台功能与大量工具；部分掌握门槛和持续打磨策略仍需防循环、时间预算与真人效果验证。

### 7.2 OpenTutor：教学动作可以变成可执行策略

仓库：[zijinz456/OpenTutor](https://github.com/zijinz456/OpenTutor)。检查提交 `0e63b44377779384ea69f30dde6e6ed59b4eb2f4`，GitHub 元数据许可证 MIT。

- [socratic_engine.py](https://github.com/zijinz456/OpenTutor/blob/0e63b44377779384ea69f30dde6e6ed59b4eb2f4/apps/api/services/agent/socratic_engine.py)：PROBE、CLARIFY、CONFRONT、SCAFFOLD、CONFIRM，分别对应探查、澄清、反例、支架提示与迁移检查；按作答质量转移，提示反复无效后改直接讲解和例题。按用户 / 课程保存状态。
- [tutor.py](https://github.com/zijinz456/OpenTutor/blob/0e63b44377779384ea69f30dde6e6ed59b4eb2f4/apps/api/services/agent/agents/tutor.py)：将策略指令接入生成过程，非孤立未使用模块。
- [teaching_strategies.py](https://github.com/zijinz456/OpenTutor/blob/0e63b44377779384ea69f30dde6e6ed59b4eb2f4/apps/api/services/agent/teaching_strategies.py)：提取解释方式、错误模式等记录，并节流和裁剪。
- [test_socratic_engine.py](https://github.com/zijinz456/OpenTutor/blob/0e63b44377779384ea69f30dde6e6ed59b4eb2f4/tests/test_socratic_engine.py)：有状态转换、退出提示循环与序列化测试，本轮未运行。

局限：响应分类输入仅截取上一条导师 / 学生消息各 500 字符，没有在这个分类函数中显式传入参考答案和课程证据；课程平均掌握度也可能掩盖当前子技能差异。所读 tutor 流程先生成，再在 _save_socratic 中分类当前学生消息、转换状态，因此本次最新回答未必及时影响本轮策略，这是代码顺序推断，尚未实际复现。教学策略提取只看到学生消息和当前教师回复，不能据此证明当前讲法已经有效。

可借鉴：教学动作词汇、持久状态、无进展退路。不照抄固定转移表或粗粒度分类；我们的策略应结合当前题、证据与最新输入，在生成回复前更新，并保留 uncertain。学生明确要求讲解时允许直接教，避免强制苏格拉底式反问。

### 7.3 OATutor：把帮助拆成可观察的小步骤

仓库：[CAHLR/OATutor](https://github.com/CAHLR/OATutor)。检查提交 `b93222e1834e650e78aba8d069a61796c3cde1c5`，GitHub 元数据代码许可证 MIT；配套题目内容库是另一资源，不能假定内容许可相同。

- [HintSystem.js](https://github.com/CAHLR/OATutor/blob/b93222e1834e650e78aba8d069a61796c3cde1c5/src/components/problem-layout/HintSystem.js)：提示依赖检查、支架子题、解锁及子题作答日志。
- [SubHintSystem.js](https://github.com/CAHLR/OATutor/blob/b93222e1834e650e78aba8d069a61796c3cde1c5/src/components/problem-layout/SubHintSystem.js)：有 scaffold 与 bottomOut 类型，子提示依赖满足后才解锁；不是按一次提示就展示完整解析。
- [aiHintGeneration/index.mjs](https://github.com/CAHLR/OATutor/blob/b93222e1834e650e78aba8d069a61796c3cde1c5/aws/aiHintGeneration/index.mjs)：所读服务端入口主要是模型流式代理，本身没有证明细致的学情诊断。

可借鉴：先提供方向、再拆一步、再给必要细节；学生在小步骤中的回答和求助过程可记录。不能把提示点击或提示后完成计成独立掌握，也不照搬帮助惩罚机制。预制支架体系不等于自动理解任意大学课程。

### 7.4 对本项目的实施建议

调研已收口为 [教学交互首轮开发方案](development/教学交互首轮开发方案.md)，该方案维护具体实施顺序与验收，本节保留研究证据。

优先顺序：DeepTutor 的自由对话 / 状态分离 → OpenTutor 的教学动作 → OATutor 的渐进提示和小步检查。不是另建第二套完整 Agent，也不是把现有学习机彻底重写。

1. 在当前任务下新增带学对话，能说“没懂第二步”“我不是这个思路”“题目有问题”，待答题可以保持打开。
2. 统一当前题、学生原作答、最新消息、实际资料、评分依据、已给提示和未解决问题的上下文，避免规则层把信息压缩丢失。
3. 模型可提出追问、提示、解释、反例、先修补缺或小检查，附简短依据；不要机械固定顺序。
4. 带学讨论、教学观察、正式作答与掌握证据分别落账；闲聊或询问不触发评分，提示后的理解不当独立成功。
5. 以同模型、同可用资料、同错误作答比较直接带学、当前系统和改进系统；教师知道的答案不泄露给学生扮演侧。先工程样例检查，再真人未见题验收。

这修正了第 6 节原先未突出教学交互的落地顺序：课程覆盖仍重要，近期先用一个真实考点验证上述带学能力，与主路径试用衔接。尚未修改应用代码或声称效果已提高。
