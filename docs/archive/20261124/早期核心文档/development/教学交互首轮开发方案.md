本文是 [04 后续路线](../04_后续开发路线与试用计划.md) 中教学交互任务的实施细化，不另立产品原则或竞争性总计划。产品约束看 [01](../01_产品原则.md)，通用契约看 [02](../02_核心开发规范.md)，已实现状态看 [03](../03_当前状态与开发接手.md)。

## 1. 已确认的问题与调研结论

目前系统已经有模型规划、题目验收、作答与状态持久化、复核和恢复，但教学互动较粗。现有 `request_hint` 主要返回预存 `analysis`；补缺进入对应阶段后转练习，缺少持续追问思路、修正误解判断、改变讲法和检查讲解效果的交互。代码锚点为 `backend/app/learning_sessions.py` 中的 `request_hint`、`advance_session` 与 `_planner_payload`。

“直接把资料交给模型可能优于当前系统”是需要复现的假设，不能写成已证明结论。现有测试和真实工程整轮也不能证明系统已经会有效教学。

调研足够支撑首轮开发，暂不扩大项目搜集或确定全局最终架构。下一步需要通过实现和同条件对照，查清上下文、行动限制及交互设计是否妨碍模型。遇到具体失败再补研究。

## 2. 开源研究转化为哪些决定

本轮实际读取 GitHub 固定提交的源码及部分测试，没有运行这些外部项目，也没有进行它们的真人效果比较。完整源码链接与局限集中维护在 [05 第 7 节](../05_技术研究摘要.md#7-2026-11-09教学交互开源源码复查)。以下是采用思想，不是决定复制代码。

| 项目与固定提交 | 参考机制 | 本项目采用 | 不直接照搬 |
|---|---|---|---|
| DeepTutor `60fb3bdfddb30b7740c7ce3bd9b28d908f2af6db` | 自由讨论与正式考核分离，题目可保持待答，实际讲解与掌握证据分开 | 对话灵活，评分和状态严格落账 | 完整 runtime、大量工具、所有掌握门槛 |
| OpenTutor `0e63b44377779384ea69f30dde6e6ed59b4eb2f4` | 探查、澄清、反例、支架提示、迁移检查及无进展退路 | 教学动作词汇、持久上下文、换策略 | 固定转移表、课程均分代表当前技能、滞后更新与短文本粗分类 |
| OATutor `b93222e1834e650e78aba8d069a61796c3cde1c5` | 分层提示、子步骤作答、依赖及求助记录 | 渐进帮助、小步检查、帮助暴露记录 | 提示惩罚、预制支架适用所有课程的假设 |

首轮不引入多 Agent 框架，不重写现有学习状态机。也不因为“苏格拉底式”就强制每轮反问；学生明确需要讲解时允许直接教。

## 3. 首轮交付与非目标

**交付：围绕一道真实题和一个明确考点，提供可连续交流、可恢复、有资料依据的带学过程；模型可选教学动作，但不会由聊天随意修改评分与掌握。**

开发可先用数据库课程中答案能核查的考点，选择概念误解、条件遗漏、方法错误、步骤错误等不同作答。试验先选一个考点，不在产品里硬编码特定课程。题目、材料和错误样本须在实际准备时确定，不杜撰现有课程样本。

第一轮包括当前题对话、渐进提示、教学动作、必要的小检查、恢复与同条件对照。暂不包括完整跨轮次教师记忆、所有学科评分、全课教学规划、复杂遗忘模型、新资料渠道或公开部署。既有覆盖台账保留并可提供证据，不把等待语义层全部完成作为本轮前置。

## 4. 用户交互契约

在学习页当前题附近增加带学交流区，保留原有正式作答入口。学生可以说“没懂第二步”“我的思路不是这样”“请直接解释”“题目似乎有问题”。聊天发送与正式提交答案必须可区分，不因模型推测而悄悄将聊天算成作答。

- 有待答题时，问答和讲解不强制关闭该题或生成下一题。
- 不能仅回复“接下来做道题”却没有实际题目。正式练习或推进必须通过现有发布与状态检查。
- 学生纠正导师的理解时，先更新当前判断；证据不足保留“不确定”，不能把所有错答直接归成概念不会。
- 提示从方向、局部步骤逐渐加深，允许直接讲解，但应记录实际帮助暴露。不能默认把整段参考解析当成一次轻提示。
- 解释没有效果时换例子、反例、拆先修或直接示范；不无限重复同一讲法，也不固定每四轮机械切换。
- 小检查用于探查理解，默认只形成教学观察，不进入正式掌握计数。需要作为独立评测时另走现有验题、作答和判分链路。
- 独立重测保持无提示规则。求助时先说明可以转带学，用户明确选择后记录本次不再独立；不自动标记答错或通过。
- 完整答案可在学习中按需讲解，但不能在“无提示独立作答”界面或接口中意外泄露。

## 5. 上下文与教学行动

每轮组装同一份可追溯上下文：课程、会话、当前题与子技能；题干和适用条件；学生实际保存作答与评分理由；最新消息及必要对话；相关资料与引用；已给提示 / 讲解及暴露程度；仍待确认的误解；当前任务和进度版本。

参考答案和评分依据属于导师侧上下文，不能原样序列化进学生端响应；只有明确讲解需要时才生成面向学生的内容。记录实际选用证据和裁剪情况。不能只把近期对错压成一个分数，或丢掉最新学生输入后再规划。

模型可以在一轮结构化响应中给出面向学生的自然语言、一个主要教学行动、简短可审查依据、引用及待确认问题。具体字段按现有网关设计，不要求先分类再生成的双调用，也不索取或展示模型内部推理。

| 可选行动 | 使用方式 |
|---|---|
| 探查 / 澄清 | 不确定卡点时，提出一个具体而必要的问题 |
| 渐进提示 | 有思路时只补一个关键连接 |
| 解释 / 例子 / 反例 | 已发现误解或用户明确要求讲解时使用 |
| 先修补缺 | 解释阻塞当前任务的最小前置知识 |
| 小检查 | 针对刚讲的内容检查，不冒充独立重测 |
| 回应异议 / 查证 | 先讨论题干、答案或判分，必要时进入现有复核 |
| 继续当前题 / 建议练习 / 暂停 | 说明建议，实际状态改变通过显式操作 |

这些是能力集合，不是固定顺序。最新输入应在生成当轮回复前参与决策。导师不能仅凭“我懂了”或自己的解释流畅就认定学生掌握，也不能根据一次对话宣布某种讲法长期有效。

## 6. 持久化与状态边界

建议使用当前学习会话 / 题目的附属对话记录，复用既有身份、来源和事件机制；是否新增表应检查现有模型后确定，以下是职责而非已存在 schema。

| 记录 | 应保存 | 能否直接更新掌握 |
|---|---|---|
| 带学消息 | 会话、题目、角色、文本、时间、请求标识与版本 | 否 |
| 教学观察 | 待确认误解、来源消息、支持依据、状态 | 否 |
| 帮助暴露 | 实际交付的提示、讲解、答案程度及关联题 | 影响独立性判断，不增加成功证据 |
| 正式作答与判分 | 继续使用已有任务 / 作答 / 复核机制 | 按既有有效性规则 |

导师生成完成不等于用户已经收到。回复在同一事务中保存并可重读，再返回；请求重试应可按标识读取同一结果。帮助已交付、保存可读但送达未知、调用失败分开记录；送达未知时不冒称已看到，也不能默认无帮助而计为独立成功。具体回执方案在首个实现阶段确定。

沿用进度版本和模型返回后校验，增加同题对话顺序检查，防止两个标签页的旧响应覆盖新状态。生成期间换题、来源移除或判分变化时，不把旧回复绑定到新题；历史可保留但标明过期，禁止旧动作推进。断线后先读保存结果，不自动重复付费请求。

对话不能直接改 `stage`、覆盖参考答案、伪造 attempt 或绕过独立验收。发现坏题 / 误判只提出查证并接入现有显式复核 / 校题入口。不能用新增导师区绕过作答前答案隐藏、重测无提示或来源有效性检查。

## 8. 对照与验收

### 对照设置

三组分别是：直接模型带学（完整、合理的导师指令，不故意削弱）、改动前系统、改进系统。固定模型 / Provider / 配置、原始资料、问题与错误作答，给予可比的轮次和调用预算。

记录两种比较：先让各组实际看到相同的相关证据，比较教学策略；再给相同原始资料、分别使用各自上下文构建，比较产品整体效果。前者有助于定位教学限制，后者才能反映检索 / 裁剪的影响。不能将“资料来源相同”冒充“模型实际看到的信息相同”。

开发回放可用固定后续学生消息检查边界；不同追问使固定脚本不再适配时，不强迫脚本继续或据此给出教学优劣。自适应模拟学生可辅助发现故障，但不能由同一个模型扮演师生后证明真人收益。评审侧答案与学生侧输入分开。

### 必须覆盖的场景

| 场景 | 期望行为 |
|---|---|
| 不知道从哪开始 | 一个可行动的起步帮助，不直接抛完整答案 |
| 答错但部分思路合理 | 保留合理部分，定位具体错误 |
| “你理解错我的意思了” | 更新判断，不沿旧归因继续教 |
| “第二步还是不懂” | 聚焦该步，换解释或例子 |
| 要求直接讲解 | 可以讲，不无限反问 |
| 质疑题目 / 答案 | 查证和解释依据，不催答，不自动判错 |
| 小检查成功 | 形成观察，不当独立掌握 |
| 独立重测时求助 | 明确独立性边界与显式转带学 |
| 生成中换题 / 移除资料 / 旧标签页 | 旧结果不写入新状态，不推进 |
| 保存成功但响应丢失 | 重读同一记录，避免重复消息 / 调用 / 证据 |

### 评价方式与完成标准

逐案标记通过、部分通过、失败和证据不足，附原句与原因；不先编造总分或教学提升百分比。关注事实正确、引用支持、错误定位、帮助粒度、修正判断、策略调整、学生控制、无进展退出、成本与耗时。

工程最低门槛：上述状态边界通过适当后端 / 前端 / 浏览器检查与构建；真实模型案例没有未修复的关键学术错误、状态污染或独立重测泄题；当前题能连续带学、恢复，并可回到正式学习流程。

行为目标：改进系统在既定案例中纠正基线具体缺陷，对直接模型没有已发现但未解释的严重退化。有限样本不能宣称统计意义上的“不劣于”或普遍更好。真人未知题独立作答和必要延迟复测另列，待取得结果才能报告学习收益。

证据建议放在隔离验收目录，包含代码版本、样本与实际上下文、三组对话、判断依据、模型配置、用量 / 耗时、状态前后差异及剩余失败。正式资料和密钥不提交。

### 当前判断

| 已确认进展 | 证据与边界 |

### 必测行为与评价

每个考点覆盖：不知道起点、部分正确但漏条件、学生纠正导师理解、解释后仍不懂、要求直接讲解、小检查条件错配、质疑依据。另测连续无进展但未主动要求暂停，以及没有明确概念词的指代追问（如“为什么刚才那一步不行”）。这些是测试场景，不规定每段教学必须走同一流程。

### 验证后再决定的设计

- **纯澄清与独立性。** 目前所有保存回复都保守计帮助，包括模型标 none 的回复；可能把澄清、异议或暂停也计入。先收集误伤案例，区分普通诊断与显式转带学的重测，再决定是否细分。不得只信模型自报 none 就取消帮助，不把送达未知当成未帮助，不静默改写历史。
