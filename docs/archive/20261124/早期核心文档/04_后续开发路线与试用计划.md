# 后续开发路线与试用计划

更新：2026-11-10。本轮依据用户最新决定重划：**先整理架构和开发流程，减少交叉修改；以本地 PR 说明划分工作。** 此顺序取代 2026-11-09 各评审中的下一步建议，不否定已实现能力。

## 1. 当前问题和安排

当前已经有连续带学、三考点对照、第二科目评分与 PDF 修复、跨轮次证据；此前的“先做三个考点”不能再作新任务。主要问题是共享模块承担过多职责、跨模块私有依赖、文档入口滞后，以及结构调整与行为扩展交叉推进。

本阶段目标是让每次改动有明确归属、依赖和验收，使下一个功能可以在边界内完成。不是推倒重写，也不要求把所有文件拆小。

## 3. 功能方向的保留与触发条件

整课语义覆盖、别名 / 子技能归并、跨轮次局部失效、专项评分、公式 / 图形全链、批次 / 校题、时间规划、备份与数据导出保留，具体缺口集中在 PR 计划第 5 节。不把它们全部塞进当前重构。

若出现丢数据、错误判分、泄题或学习无法继续等真实阻塞，允许单独前置最小修复卡；写清证据、范围及与结构 PR 的关系，再回到主顺序。一般新需求先入保留清单，在维护阶段出口后决定，不随每次评审改写当前方向。

多人部署、复杂调度、重型图谱、多 Agent、模拟卷、更多渠道继续后置，除非用户改变目标或实际证据表明必要。

## 4. 开发与验收规则

- 一次一个主要实现 PR；共享文件的修改集中到明确卡片，接口变更和调用方同批验证。
- 文件移动 / 函数提取与提示词、评分、模型调用、数据库或 UI 行为修改分开。
- PR 完成要有范围内的验收，不靠累计测试数量或文件数量证明架构改善。
- 工程、模拟接口、真实模型和真人分开报告；历史结果不能冒称当前执行。
- 有效资料、无提示独立性、显式评分 / 推进、人工纠错留痕与历史一致性不因重构放松。
- 依赖、文件边界、风险、验证和回退使用[本地 PR 模板](../../../../.github/pull_request_template.md)。不要求上传 GitHub。

## 5. 真人试用入口

沿用[真人试用包](../../../../evals/tutoring/trial-protocol.md)，不复制模板。记录环境、代码版本、题包、前测原答、帮助、观察者介入、未见题后测和可行的隔天结果。独立安装、恢复演练、校题负担、耗时和用量也应记录。

固定回放、开发脚本输入与一次重测不能替代真人效果；1–2 人试用只反馈具体问题，不输出普遍教学提升比例。
