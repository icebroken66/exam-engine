## 文档效力与维护

1. 用户最新明确决定优先；产品范围看 01，功能契约看 02，实际状态看 03，开发顺序看 04。
2. 目标、方案、实现分开。完成状态附代码、验证和边界，不能从研究建议直接勾选完成。
3. 当前状态直接改写 03，任务直接改写 04，历史证据追加 records，不再堆多个“最新进展”。
4. 功能变化同步改相关规范。当前 PR 范围只维护代码仓库 docs/development/开发拆分与PR计划.md；03 维护状态、04 维护阶段、records 维护历史，旧首轮方案不再追加待办。
5. 历史中的“未提交”“下一步”“未完成”只表示当时，不覆盖当前快照。
6. 本目录仍在 exam-engine Git 仓库外；本地 PR 计划与模板放入仓库，便于审阅。未自动搬迁整个文档库。代码维护已固定本地 PR-05 提交 ff7bac3；本目录不在该 Git 仓库内，未推送或创建远端 PR。
